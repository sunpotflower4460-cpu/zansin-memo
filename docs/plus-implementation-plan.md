## 2. 実装順の全体

各Phaseを小さなPRへ分ける。最初のPRで6画面・保存形式・SDK・バックエンドを同時に変更しない。

## 3. Phase 11.0 — 保存と技術の土台

### 対象

既存の [types](../src/domain/types.ts)、[gardenCommands](../src/domain/gardenCommands.ts)、[gardenModel](../src/data/gardenModel.ts)、[gardenStorage](../src/data/gardenStorage.ts)、[gardenWriter](../src/data/gardenWriter.ts)、[useGarden](../src/data/useGarden.ts)、[exportFormat](../src/utils/exportFormat.ts)。追加する型・モジュールの最終名は既存構成に合わせる。

### 実施すること

1. [AI・データ契約](plus-ai-data-contracts.md)に従い、v2からv3への非破壊移行・正本・引用・版・見方・提案・同意の単位を実装する。`SeedConnection`と現在の`Seed.synthesis`の意味を変えない。
2. 既存writerへ新コマンドを統合する。画面から別キーへの独自書込みを増やさない。データ保存と購入権利の検証結果を同じ信頼境界に置かない。
3. 旧形式、不明な新版、途中終了、破損、応答不明、重複操作、容量不足でデータを空にしないことを確かめる。
4. 送信禁止と候補への表示除外を別設定にする。未設定の既存データを外部送信許可へ移行しない。
5. 地図描画、レイアウト計算、画像/PDF生成、購入のネイティブ依存について、Expo/RNの採用バージョンで小さく実証する。SDK名は最新の一次資料で確認して記録する。
6. 50/500/2,000/5,000件、長文、多数接続、未接続、多数の下書き・版を含む架空の試験データを用意する。ユーザーの実メモをテストfixtureへコピーしない。

### 完了条件

- 移行を再実行しても重複・日時捏造・外部送信が起きず、失敗後も元データへ到達できる。
- JSON/テキスト書出しに新しいユーザー作成物を含められ、旧コアも読める。復元UIの有無を正直に表示する。
- 同じ操作IDの再試行で接続・芽・作品・利用枠が二重にならない設計が実装で守られる。
- 保存形式の版、ローカルデータ、利用権、秘密情報を分けている。
- 高密度地図と組版の候補方式を実機で比較する計画があり、Webだけでネイティブ対応を完了扱いしない。

このPhaseで本番の購入画面や外部AIを有効化しない。必要な型・開発専用アダプター・feature flagを作り、本番設定は閉じておく。

## 4. Phase 11.1 — 地図を商品品質にする

### 対象

[LocalMap](../src/components/LocalMap.tsx)、[ConnectionsPanel](../src/components/ConnectionsPanel.tsx)、[mapLayout](../src/utils/mapLayout.ts)、[GardenScreen](../src/screens/GardenScreen.tsx)、[SeedsScreen](../src/screens/SeedsScreen.tsx)、[theme](../src/styles/theme.ts)、[App](../App.tsx)。全体図は専用の部品・画面へ分離し、現在の基本図を巨大な条件分岐へ変えない。

### 分割例

1. 全体・周囲・リストの同じ対象集合と移動文脈。
2. まとまり・折りたたみ・情報量を段階表示する拡大と検索。
3. 配置の保持、固定、手動整理の代替操作、再配置プレビューと戻す操作。
4. 保存した見方、詳細・アトリエへの往復、端末の大きい文字・読み上げ・速度。

### 完了条件

- [地図設計](plus-map-design.md)の受入例を満たす。まとまりから確定接続を推定しない。
- A–BとB–Cだけがある時、A–Cの線を作らない。遠い要素の省略を件数や一覧で説明し、全件へ到達できる。
- 追加した種があるだけで、保存した配置・ピン・選択を全て作り直さない。
- 無料の周辺図・全文・リスト・基本移動・アクセシビリティを保つ。
- 50/500/2,000/5,000件で、重なり・文字切れ・誤タップ・応答を測る。速度は計測環境とともに残す。
- 端末の大きい文字、VoiceOver、Reduce Motion、片手操作を含む品質を確認する。

AIがなくてもこのPhaseの価値を確かめる。地図だけを先に「購入済みでないと原文が読めない画面」へ置き換えない。

## 5. Phase 11.2 — AIは候補として届ける

### 対象

[aiAssist](../src/domain/aiAssist.ts)の境界、[links](../src/utils/links.ts)のローカル候補、[suggestionPrefs](../src/data/suggestionPrefs.ts)、候補パネル、送信設定、追加のサーバーアダプター。既存の語句一致を実AIの精度評価として扱わない。

### 分割例

1. 外部通信なしで、候補・理由・原文・採用・見送り・失効を画面とコマンドで一周させる。
2. 対象選択・送信同意・送信禁止・由来を引き継ぐ除外・取り消しの検証。
3. 予算、利用権、リクエストID、構造化結果、原文照合を持つサーバー経路。
4. 本物のモデルによる日本語の評価。採用率だけでなく、根拠の正しさと発見の役立ちを観察する。

### 完了条件

- 候補を読む、見送る、アトリエへ持ち込む操作で、確定接続を増やさない。
- 本人の採用時だけ既存の接続コマンドを通り、原文・権限・対象の変更を再検証する。
- 遅れて届いた結果、二重応答、送信中の同意撤回、材料削除・編集を無効化できる。
- AIの理由に存在しない引用があれば、その結果を利用可能な候補として見せない。
- 外部送信と課金の同意は分け、同意しない場合も地図と自分の文章を扱える。
- APIキー等をアプリ・ログ・repoへ含めない。運用コスト上限とユーザーの利用枠の扱いを検証する。

提供者・モデル・保存期間が未確定なら、本番通信を閉じたまま仕様とローカル機能を完成させ、未解決の設定項目を具体的に残す。

## 6. Phase 11.3 — アトリエ

### 対象

[SynthesisScreen](../src/screens/SynthesisScreen.tsx)、[SynthesisCard](../src/components/SynthesisCard.tsx)、[gardenCommands](../src/domain/gardenCommands.ts)、新規アトリエ画面・版管理・材料棚。既存の無料の芽の入口は残す。

### 実施と完了条件

- [アトリエ設計](plus-atelier-collection-design.md)に従い、選択材料の由来を保ったまま制作スペースを作る。
- 下書きを自動退避し、明示した節目だけを比較可能な版にする。キー入力ごとの無制限な全文履歴を作らない。
- A案/B案を比べ、好きな一節を固定し、以前の版を参照して新しい下書きへ戻せる。
- AIの短い案は独立した候補。選んだ案だけを本人の操作で下書きへ入れ、固定した文を黙って変更しない。
- 芽の保存先・既存の芽の有無を表示し、現行の期待本文照合と上書き保護を通る。
- 画面離脱・日本語変換・キーボード・保存失敗・再起動で入力を守る。
- 採用後に材料の原文を変更しても、過去の版と採用時の引用は黙って更新しない。削除・送信禁止時はデータ契約の扱いを適用する。

## 7. Phase 11.4 — 作品集

### 対象

新規作品集一覧・編集・プレビュー・出力モジュール、[exportFormat](../src/utils/exportFormat.ts)、[exportUtils](../src/utils/exportUtils.ts)、保存コマンド。

### 初回の範囲

ことばのカードと、地図・文章を一緒に置く1ページ。少数の丁寧なテンプレートから始め、文字・余白・線・題名・由来を整える。複数ページ冊子は別の後続作業とする。

### 完了条件

- 残す内容、順序、題名、含める材料、見え方を本人が選べる。含めない原文を出力しない。
- 作品は採用時のスナップショットを持ち、元メモ更新は「更新あり」として別に扱う。
- PNG等の画像とPDFを実際に出力し、長い日本語・絵文字・改行・フォント・線・余白をファイル自体で確認する。
- 1ページへ入りきらない場合は、内容を黙って削除したり読めない縮小をしたりせず、範囲や形式を選び直せる。
- プレビュー、作品集への保存、外部共有を別操作にする。共有を取り消しても作品は残る。
- 由来を開けば、元の地図の選択・範囲へ戻れる。材料が削除済みなら状態を伝え、本文を勝手に復活させない。
- 出力失敗・低容量・アプリ終了で原文や作品を失わず、一時ファイルの扱いも明確である。
- 失効後も、既存作品を保存済み形式・テンプレート・配置設定でPNG/PDFへ再出力できる。手動編集後の文章と削除済み引用の非表示を反映し、標準出力と全文の取り出しも [利用権表](plus-commerce-validation.md)どおりに保つ。

## 8. Phase 11.5 — 購入と利用権

課金は [課金と品質検証](plus-commerce-validation.md)の状態表を正本として実装する。課金UIから各機能への分岐をばらばらに増やさず、利用権サービスと機能単位の判定へ集約する。

### 販売前に確定するもの

| 項目 | 確定するために必要な材料 | 未確定でも進められること |
|---|---|---|
| 販売方式・期間・価格 | 継続価値、原価、観察、ストア仕様 | 料金表示の状態・閉じる・復元の画面 |
| 試用方式・日数 | 内容を体験できる範囲、StoreKitの対象条件 | ローカルの自分の地図プレビュー |
| AI利用枠と更新期間 | モデル原価、長文上限、予算、失敗時扱い | 枠表示・不足・再試行・重複防止 |
| 購入SDKと商品ID | Expo互換性、実機試験、ストアの設定 | アダプターと開発用状態fixture |
| AI提供者とデータ契約 | 保存期間、学習への利用、削除、リージョン等の実条件 | 同意画面の構造と送信禁止のローカル判定 |
| AI利用者の識別 | サーバーでの利用権検証、別端末・復元時の枠共有方針 | 未認証・オフライン・復元中の画面 |

### 完了条件

- 購入成功・保留・取消・失敗・復元・失効・返金・猶予・オフラインをSandbox/必要な実機で確認する。
- 本番商品の価格・期間はストア情報を表示し、仮説価格や偽の割引を固定しない。
- 購入しただけでAI同意・クラウド同期同意を作らない。
- 利用権取得失敗でも自分の文章を閉じ込めない。ローカルの自己申告だけでサーバーAI権利を発行しない。
- 成果物の閲覧・基本編集・標準書出しを失効後も保ち、購入のやり直しをアクセスの条件にしない。
- App Privacy・利用規約・プライバシーポリシーが、実際のSDK・送信・保存・削除と一致する。

## 9. Phase 11.6 — 一周と商品品質の検証

### 必ず一周させるケース

| ケース | 確かめること |
|---|---|
| AIなしのPlus | 地図を整える→材料を持ち込む→自分で書く→芽→作品集→元の地図 |
| 候補を採用する | 原文と理由を読む→採用→実線→同じ候補の再送でも1本 |
| 候補を採用しない創作 | 点線のまま材料にする→芽と作品を保存→接続は増えない |
| 思い直す | 下書き比較→芽を見直す→以前の作品は保つ→本人が更新を選ぶ |
| 送信中の変更 | 同意撤回/原文変更/削除→旧応答を破棄→入力は残る |
| 保存障害 | 移行/下書き/採用/作品保存の途中失敗→再試行→重複せず復旧 |
| 購入失効 | 既存の見方・文章・作品を読む/基本編集/標準出力→新規AIは契約どおり停止 |
| 大量・読み上げ | 高次数/長文/大きい文字でも対象を探し、原文を読み、元の場所へ戻る |
| 削除と書出し | 削除済みの引用や送信禁止の由来が、許可のない経路から外部へ出ない |

詳細の受入表は [課金と品質検証](plus-commerce-validation.md)を使う。`npm run check`はコード変更時の基礎ゲートであり、実機・AI・課金・PDF品質の代用にしない。関係ない全テストを繰り返さず、変更した契約と具体的な残リスクを検証する。

## 10. 変更の出し方と完了報告

- 各PRの本文に、Phase、利用者に起きる変化、対象・対象外、移行、確認方法と実結果、未検証範囲、次Phaseを書く。
- 変更した設計と実装を照合し、仕様を都合よく縮めて合格にしない。達成が難しい場合は、どの体験が不足するかを具体的に残す。
- マップ計算、AI、アトリエの任意提案、作品の組版、課金は独立して無効化できるようにする。機能を閉じる際にも保存したデータを消さない。
- 新版の保存形式を旧アプリへ安全に戻せるとは仮定しない。後戻り時は新形式を読む互換修正版か、保持データを使う復旧手順を用意する。
- 基本の保存・手動接続・自分の芽・全文の取り出しが壊れた場合は販売を進めず、その経路を先に修正する。

今回のdocs追加の完了は、6文書が参照でき、現行設計との優先関係が明確で、仕様間の矛盾・相対リンク・変更範囲を確認し、repoへ保存したこと。Phase 11の実装完了を意味しない。
