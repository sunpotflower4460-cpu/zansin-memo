## Phase 10.3 — 材料から、自分の芽を書く

### 実装したこと

- **芽の保存コマンド**（`promoteToSprout`）: 芽の文を、元の本文とは別欄（`synthesis`）に保存。中心の原文は必ず材料に含み、他の材料は本人が選んだ0件以上。材料は「表示して確認した文章」と現在の文章が一致するときだけ採用し、変わっていれば拒否（入力は残る）。他の芽を材料にするときは、元のメモか芽の文かを区別して採用した文だけを保存し、その材料を再帰的に複製しない。件数・日数の解禁条件なし。育ち方は種・保管→芽、木は降格しない。材料にしても線は増えない。
- **すでに芽がある中心への新規作成は拒否**（`center_has_synthesis`）。見直しは `review` を明示。文章だけの見直しは材料のスナップショットを保持し、採用時刻（`promotedAt`）を動かさない。
- **種として考え直す**（`reconsiderSynthesis`）: 育ち方を種へ戻し、考えと材料を残す。現在の芽としては数えない。「この考えで芽にし直す」で再採用。
- **保存直後の元に戻す**（`undoPromotion`）: 以前の育ち方・芽へ戻し、書いた文章は下書きとして残す。保存後に別の見直しが入っていれば巻き戻さず拒否。常設の「芽を見直す」「種として考え直す」とは別の操作。
- **芽の画面**（`SynthesisScreen`）: 「この芽は、このメモに残ります」と中心を予告（新規は「変更する」）。中心の原文は材料に固定。つながっているメモは候補として並べるが、選ぶまで材料にしない（全文表示つき）。「材料を追加」で全件から検索して選べる。入力の問いは材料の有無で切り替え。保存は一言を書くまで押せない。「あとで考える」で下書きに残す。材料・文章は下書きとして保存され、詳細から再開できる。
- **詳細**（`SynthesisCard`）: 「できそうなこと（芽）」を表示。「この芽を作ったときの材料」を、現在のつながりとは別の見出しで表示。材料ごとに元のメモか芽の文かを区別し、現在の文と違えば「材料に更新あり」、削除済みなら本文を出さず「最近削除した種」へ案内。以前からの育ち状態だけのものは「芽の文章はまだ書かれていません」と表示し、文章を作らない。旧Transformは「別の形に書き出す」（芽ではなく書き出しの補助）へ移した。
- **一覧**: 複数選択のトレイから「ここから芽をつくる」（最初に選んだメモが中心の初期値、ほかは材料に）。芽の文は一覧に表示し、検索対象。

## Phase 10.2 — 自由に残す・後からつなぐ・図で見る

### 実装したこと

- **書く**（`WriteScreen`）: 見出し「メモを書く」・補助文「なんとなくでも、そのままで大丈夫。」・主ボタン「保存する」（設計§4の文言）。タイトル・カテゴリ・接続先を決めずに保存でき、保存が確定すると書く画面に「保存しました」のカードを残し、任意の「別のメモとつなぐ」「続けて書く」を出す（初回だけ「あとからつなげられます」の一文）。
- **メモを足す**: 詳細から「メモを足す」→ 接続先の抜粋つきで書き、「保存してつなぐ」でメモとつながりを1回の更新で確定。「単独のメモとして残す」に切り替えても本文は消えない。保存後は元のメモの詳細へ戻る。
- **種一覧**（`SeedsScreen`）: 検索と4つのビュー（すべて／まだつないでいない／つながり／芽）。検索は本文・題名・カテゴリ・芽の文の全件が対象で、一致した語句の抜粋を表示。育ち方・カテゴリ・並び替えは折りたたみ。件数つき、条件の一括解除、検索0件と記録0件の区別。長い本文は「全文を読む」で展開。検索・ビュー・選択・スクロール位置は詳細から戻っても保持。
- **選んでつなぐ**: 「選ぶ」で複数選択（長押し不要・チェックと文字ラベル・選択順つき）。2件は「2つをつなげる」（既存なら「つながっています」）、3件以上は中心を選んで、作られる線だけをプレビューしてから追加（選んだ全員同士は結ばない）。選択トレイは検索や切替でも残る。
- **局所マップ＋等価リスト**（`ConnectionsPanel` / `LocalMap` / `mapLayout`）: 中心と直接つながるメモだけを表示。上限6件で「ほかN件はリストで見られます」。マップ／リストを切り替えても同じ操作（中心を移す・全文・どうつながる？の一言・つながりを外す）。幅に応じて行数を変える配置で、狭い端末でも重ならない。A-B・B-Cから A-C の線は描かない。
- **中心の移動と戻り**: 「このメモを中心に見る」で移り、「ひとつ前のつながりへ」「最初のメモへ戻る」で戻る（親子ではなく、見てきた順）。
- **詳細**（`SeedDetailScreen`）: 本文はまず読む画面で、編集は「編集する」から。編集中の内容は下書きとして保存され、戻る・再起動後も続きから再開。別の操作が先に確定していれば警告し、入力は残したまま確認を促す。「戻る」だけでは本文を書き換えない。
- **庭**: 「つながりのあるメモ」（本人が結んだ直接のつながりだけ。連結した集団を「同じ話」とまとめない）。

## Phase 10.1 — 保存契約・互換データ

### 実装したこと

- **データモデル**（`src/domain/types.ts`）: 無向の `SeedConnection`（正規化したペアのJSONをIDにする。`origin: manual | legacy`、旧データの日時は持たない）、別欄の `SeedSynthesis`／`SynthesisSource`（型のみ。画面は10.3）、`Draft`、`GardenStoreV2`（`revision`・`lastMutationId`・seeds・connections・drafts）。`Seed` から `relatedSeedIds` を外し、正本を Connection に一本化。
- **正規化・移行**（`src/data/gardenModel.ts`）: v1→v2 を決定的に移行。片方向／双方向／重複は同じ1ペアに、自己参照・不存在参照は可視接続にせず診断に数える。削除済みSeedへの接続も保持。芽の文章・接続日時は作らない。旧 `continuedFromId`（このブランチ限定の試作項目）も旧接続として吸収。
- **読込・削除**（`src/data/gardenStorage.ts`）: 起動時の順序は ①削除中marker ②v2本体→v2のlastGood（壊れていてもv1を黙って最新にしない）③v2が無いときだけv1。未知の新しい版・壊れたデータ・読込失敗は、空として上書きせず変更を停止。v1原本は触らない。全データ削除は「marker→書込み停止→対象キー削除→空のv2を確定→照合→marker解消」で、途中終了時は次回起動が再開。
- **単一writer**（`src/data/gardenWriter.ts`）: 全ての保存を1本のキューで直列化し、最新の確定状態にコマンドを適用。主保存の成功が確定点で、lastGood の失敗は「本保存は成功・バックアップだけ失敗」として別扱い。書込みに失敗しても確定状態を進めず、同じコマンドIDでの再試行が二重作成にならない。応答不明（書けたのに失敗が返る）は読み直して確認。下書きは待機中のものを1件にまとめ、確定操作が消した下書きは復活させない。下書きだけの更新はlastGoodを書かない。
- **コマンド**（`src/domain/gardenCommands.ts`）: captureSeed / connectSeeds / captureAndConnect / connectFromCenter / disconnectSeeds / setConnectionNote / updateSeedFields（期待版つき）/ addTransformOutput / softDeleteSeed / restoreSeed / touchResurfacing。IDと時刻は呼び出し側が最初に確定。
- **画面側**（`App.tsx` ほか）: 保存が確定してから成功を表示し、失敗は消えない表示で入力を残す。保存中は二重に押せない。詳細の編集は期待版つきで、先に別の更新が確定していれば上書きしない。戻る操作は保存の確定を待つ。
- **書出し**（`src/utils/exportFormat.ts`）: JSONは削除済み・接続・芽と材料・下書きを含む全データで、実行前に範囲を明示。テキストは非削除のメモ・接続・芽と材料を読める形で出し、削除済み材料の本文は出さない。どちらも「書出しから復元する機能は現時点でない」と明記。
- **旧実装からの整理**: 旧 `AsyncStorageSeedRepository`・`saveState`・別キーの下書き保存を撤去。本ブランチで先行試作していた「つながりのまとまり」カードと「話のながれ」は、連結した集団を一つの話と断定する表示だったため撤去（設計§5・§10に反する）。

### 未検証・残課題（10.1）

- iOS実機での AsyncStorage への書込み時間・容量。重い5,000件（約14MB）では、1回の保存でこの大きさを書くことになる。下書きだけの更新ではlastGoodを書かない対策は入れたが、端末で入力の応答を測る必要がある。必要なら保存頻度・重複データを見直す（DB導入は前提にしない）。
- 終了直前の未確定入力の保存はOS任せで、保証しない。
- 複数ブラウザタブからの同時編集は対象外（設計§5.1）。
- 書出しファイルからの復元UIは無い（設計どおり）。
- D06・D07・D08・D10・D13・D15 は、芽（10.3）・図（10.2）・例（10.4）の実装後に確認する。
