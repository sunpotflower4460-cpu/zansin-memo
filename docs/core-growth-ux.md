# Core Growth UX — 残す・あとからつなぐ・芽にする

作成日: 2026-11-26（日本時間）

状態: **公開前に実装・検証する設計。実装済みという意味ではない。**

確認した実装: `ff0d8906ae2a07aa17da8492e5f342a2bfee6077`

本書は、思いつきを種として残し、後日メモ同士をつなげ、見えてきた可能性を芽として残す画面仕様を定める。
全体方針は [Core Growth Loop](core-growth-loop.md)、データ・移行・保存は [Core Growth Data](core-growth-data.md)、実装順と検証は [Core Growth Plan](core-growth-plan.md) を参照する。
既存の低圧入力・ローカル保存・再会・復元を生かす。公開前の中核体験として、基本のつながり表示までを含める。

## 1. ユーザーに約束すること

> なんとなく思ったことを残す。あとからつながりを見つける。できそうなことが見えたら、芽にする。

| 言葉 | 画面で伝える意味 | 判断しなくてよいこと |
|---|---|---|
| 種 | 残した思いつきや気持ち | 役に立つか、分類は何か、何に育つか |
| つながり | 自分が「関係がありそう」と結んだメモ同士の関係 | 親子、方向、正しい関係の種類 |
| 栄養 | ある考えを育てる時に助けになる、つながったメモの役割 | メモを別の種類へ変更すること |
| 芽 | 材料を見て、自分の言葉にした「なら、こうできるかも」 | 実行期限、計画の完成、成功の保証 |

- メモは単独のまま残せる。種のままでも価値があり、芽にする義務はない。
- 保存する時に、既存の種との関係やカテゴリを決めさせない。
- AとBをつなぐ時は等価に扱う。親の選択、栄養かどうかの選択を要求しない。
- 関係を結んだだけでは、芽の根拠として採用したことにならない。芽を書く時に材料を選ぶ。
- 同じメモを複数の考えに使える。つなぐ操作で移動・複製・本文結合をしない。
- 栄養の数、日数、AIの採点で自動昇格しない。本人の発見を芽として残す。
- 気分・カテゴリ・大切度は補助設定。主要操作より先に選ばせない。
- 木・森・水脈などの比喩を初回説明へ増やさない。既存の木・保管データは引き続き開ける。

## 2. 画面をまたぐ共通の扱い

「書く」「探す」「つなぐ」「育てる」を混同しない。入口は多くても、同じ操作には同じ文言を使う。

| やりたいこと | 主な入口 | 操作の結果 |
|---|---|---|
| 思いつきを残す | Home / 書くタブ | 独立したメモが保存される |
| 後からAとBを結ぶ | 種一覧の複数選択 / 詳細 | 2件の間につながりが表示される |
| 今見ている種に考えを足す | 詳細の「メモを足す」 | 新しいメモの保存と接続が一度に完了する |
| つながったものを眺める | 詳細 / 庭 | 局所マップと等価リストで読める |
| 可能性を言葉にする | 「ここから芽をつくる」 | 元の言葉と材料を残して、芽の文が保存される |

画面内では「ID」「正本」「無向エッジ」「synthesis」などの実装用語を表示しない。
データ上は無向 `Connection` を正本とし、現在の中心Seedと同じIDに、原文とは別の `synthesis` を保存する。
「中心」は今見ている対象の意味であり、つながりの上下関係ではない。

## 3. Homeと初回の入口

### 空の状態

見出し: **思いつきを残し、つなげて、できそうなことへ。**

説明は次の3行までを基本とする。

1. まとまっていない一言も、種になります。
2. あとから「関係がありそう」と思ったメモをつなげます。
3. できそうなことが見えたら、芽として残します。

主ボタンは `メモを書く`。副ボタンは `例で使い方を見る`。
空の「今日の種」「最近の種」「芽」「木」をいくつも並べず、最初の入力へ進める一つの空状態にする。
説明を読まなくても書ける。チュートリアル完了、ログイン、課金、カテゴリ登録を条件にしない。
起動時のブランド演出は入力可能になるまでの待機を追加しない。毎回1.2秒待たせる現行設定を見直す。

### メモがある状態

日常の優先順は `メモを書く`、今日再会する種、最近触れたつながり、最近のメモとする。
庭便りはそれらの後に置き、入力や再開を妨げない。設定・書き出し・全削除のSettings全面分離は既存Phase 9の独立課題とし、今回の一周の前提にはしない。中核操作を前面に出し、既存の設定入口へのアクセスを維持する。
再会したカードから `メモを足す` と `つながりを見る` へ進める。
再会の理由は「しばらく見返していない」など、実際の選出理由だけを表示する。
利用しなかった日数や「まだ育てていない」を責める表現、赤い未達バッジ、連続記録を置かない。

## 4. Write — まず残す

見出しは `メモを書く`。補助文は `なんとなくでも、そのままで大丈夫。`。
最初に見える入力欄は本文。タイトルとメタ情報は任意で、詳細を開いた時に設定できる。
主ボタンは `保存する`。種・栄養・芽の種類を選ぶ工程を前置きしない。
本文が空白だけの場合は保存を無効にし、入力内容はそのままにする。

### 通常の保存後

永続化の成功を確認してから `保存しました` と表示し、保存した本文の短いカードを残す。
カードには任意の `別のメモとつなぐ`、`続けて書く` を置く。
初めての保存時だけ `関係することを思いついたら、あとからつなげられます。` と添えられる。
関連候補のシートを毎回自動で開かない。保存後すぐ閉じても、一言を残す目的が完了する。
次の画面へ進んでも「今保存したメモ」がわかる位置へ戻れるようにする。

### 特定の種から「メモを足す」

入力欄の上に接続先の本文抜粋を表示する。例: `このメモにつなげます: 散歩写真が溜まる`。
主ボタンは `保存してつなぐ`。接続先をもう一度探させない。
この操作は新しいメモの保存と関係の保存を一つの操作として扱う。部分的な成功を完成扱いしない。
`単独のメモとして残す` に切り替えられる。切り替えで本文を消さない。
追加後は元の種の詳細へ戻り、加わったメモと線が見える位置を示す。
「元の文章を直す」は別の `編集する` に置き、栄養追加で過去の原文を上書きしない。

## 5. 種一覧 — 溜まってからでも見つけられる

一覧上部に検索と4つのビューを置く。フォルダ分けやカテゴリ作成は前提にしない。

| ビュー | 表示対象 | 空状態の例 |
|---|---|---|
| すべて | 削除済み以外のメモ | ここに思いつきを残していけます。 |
| まだつないでいない | 有効なつながりがないメモ | 今あるメモには、つながりがあります。 |
| つながり | 有効なつながりを持つメモ | 関係がありそうなメモを2つ選ぶと、つなげられます。 |
| 芽 | 芽・木の状態のメモ。芽の文があれば主に表示 | できそうなことが見えたら、芽として残せます。 |

「まだつないでいない」は作業待ちの意味にしない。警告色や未処理件数の通知を付けない。
既存の木・保管・カテゴリ等は追加フィルターで閲覧でき、アップデートで見えなくしない。
旧データで状態だけが芽・木の場合も一覧へ含め、原文と「以前からの育ち状態」を表示する。新しい合成文があると誤認させず、芽を新しく書いた件数には混ぜない。保管は「すべて」では表示し、提案からは除外する。検索・追加フィルターには対象範囲を表示し、一括で条件を解除できる。
検索結果0件と、記録自体0件を区別する。前者は `検索条件を解除`、後者は `メモを書く` を案内する。

### 検索とカード

- 本文・任意タイトル・カテゴリ・保存済みの芽の文を検索する。
- 検索は表示済みの先頭20件などに限定しない。2,000件以上でも全対象を探せること。
- 一致した語句を短い抜粋で示す。芽の文が一致した時はその文が見えるようにする。
- 同じ冒頭のメモを区別できるよう、日付・タイトル・全文を読む入口を備える。
- カードには本文、日付、状態、つながり件数を表示する。大切度を常に最前面に出さない。
- 長い本文は省略できるが、選ぶ前に全文を確認できる。16文字のチップだけで選ばせない。
- 通常の並び順は最近の更新。並び替えとカテゴリは補助操作へまとめる。
- 再会表示回数などの背景更新だけで一覧が並び替わらないようにする。
- 検索文字・フィルター・スクロール位置は詳細から戻っても保持する。

### 2つを選んでつなぐ

一覧の明示的な `選ぶ` から複数選択に入れる。長押しだけを唯一の入口にしない。
最初の選択後も検索・ビュー切り替えができ、画面下の選択トレイに選んだメモを保持する。
選択中のカードにはチェックと文字ラベルを出す。色だけで表さない。

- 2件選択: 主操作 `2つをつなげる`。選択した2件の抜粋を確認できる。
- 1件選択: `もう1つ選ぶ`。接続先を勝手に決めない。
- 3件以上: 全組み合わせを自動で結ばない。`つなぎ方を選ぶ` で中心と接続先をプレビューする。
- 中心に複数つなぐ場合は、最初に選んだメモを中心の初期値とし、変更可能にする。
- 確認画面には実際に作る関係だけを表示し、既存の関係は `つながっています` と区別する。
- キャンセルは選択の解除であり、メモの削除ではない。

## 6. 接続後に、関係が目に見えること

成功トーストだけで終わらせず、つながりを表示する画面へ移る。
2件をつないだ直後には、両方のメモとそれを結ぶ一本の線を示す。
既に接続済みの場合は重複した線やメモを作らず、その関係を開く。
初回だけ `このつながりを見ながら、思いついたことを足せます。` と短く案内できる。
その場の主な次の操作は `メモを足す` と `ここから芽をつくる`。
どちらも必須ではない。戻って他の思いつきを残すことも一つの完了になる。

## 7. 詳細 — 原文、つながり、芽を同じ場所で読む

詳細の基本順序は次の通り。

1. 元のメモ本文と日付。本文はまず読める状態とし、編集は明示操作にする。
2. `メモを足す` / `保存済みのメモをつなげる`。
3. つながりの局所マップと、同じ内容を読むリスト。
4. 保存済みの芽、または `ここから芽をつくる`。
5. いったん種に戻した時のまとめた考え、カテゴリ等の補助情報、保管・削除。

現在の `詳細を編集する` の奥にある関連選択は主導線から外し、この場所へ統合する。
つながったメモは全文を開け、どちらから見ても同じ関係を確認できる。
関係のメモは任意で `どうつながる？` と書ける。共通点だけでなく、違い・疑問・反対の気づきも残せる。
一般のつながりを、賛成・正しさ・芽への採用済みの証拠として表示しない。
原文の誤字修正と、考えが変わった記録は別操作にする。後者は新しいメモや芽の見直しで残す。

## 8. 局所マップと等価リスト

**基本の局所マップと等価リストはPhase 10.2で実装する公開前必須項目。大規模整理と候補の強化はPhase 10.5。**
最初から全メモを一枚のグラフへ描かない。今見ているメモと、その周囲を読める大きさで示す。

### 基本マップ

- 現在見ているメモを中心に、直接つながったメモを配置する。
- 通常のつながりは矢印のない線。線の太さや色で正しさ・価値・強さを勝手に採点しない。
- 初期の表示上限は周囲6件を目安とする。今回つないだ相手、ユーザーの選択中の材料を優先する。
- 6件は描画上の上限であり、保存・探索の上限ではない。残りは `ほか24件を見る` のように明示する。
- 選択した材料が上限を超える時も、材料リストに全件を残し、見えていない件数を知らせる。
- ノードの短文を読める大きさを保つ。全文は選択で開け、名称の重なりを放置しない。
- 移動・ズームを要求しなくても、表示された関係を読める初期位置にする。
- ノードをタップすると概要と `このメモを中心に見る` が現れる。タップだけで突然中心を飛ばさない。
- 画面にない関係は描かない。A-BとB-Cがあっても、A-Cの線を補完しない。
- 選択中を示すハイライトと、保存済みの関係を示す線を区別する。
- 解除操作は線を正確にタップする必要がないよう、メモカードのメニューにも置く。

### 等価リスト

`マップ` / `リスト` を切り替えられる。リストは簡易版ではなく、同じ操作ができるもう一つの表示とする。
中心メモと、直接つながる全メモの本文抜粋・日付・任意の関係メモ・操作を表示する。
関係をたどる、中心を替える、全文を読む、解除する、材料を選ぶ、芽を作る操作を全て提供する。
VoiceOver、文字拡大、動きを抑える設定でも、図を解釈せずに一連の操作ができるようにする。
マップの表示上限によりリスト側のメモが失われることはない。切り替えても選択と中心を保持する。

### 位置を見失わない

上部に `いま見ているメモ` とその抜粋を常に示す。
中心を切り替えるたびに戻り履歴へ積み、`ひとつ前のつながりへ` と `最初のメモへ戻る` を用意する。
履歴は現在の閲覧経路であり、関係の親子階層として描かない。
詳細から一覧へ戻ると、元の検索・ビュー・スクロール位置へ戻る。
接続や芽の編集を中断して関係をたどっても、作業中の選択と本文を保持する。

## 9. 芽をつくる — 自分の可能性を書く

入口は詳細・接続直後・一覧の複数選択。必要な材料を並べてから、本人が新しい一文を書く。
直接つながっていないメモを一緒に選んでもよい。材料選択のために余計な関係を自動作成しない。

### 中心と材料

詳細から始めた時は現在のメモを中心にする。複数選択から始めた時は最初に選んだメモを中心にする。
画面に `このメモから芽をつくる` と中心の抜粋を表示し、新規作成中は `変更する` を用意する。
中心を改めて選び直すことを必須にしない。中心の変更は元のメモや既存のつながりを書き換えない。
中心の元本文は必ず材料に含める。他の材料は0件から選べ、周辺のメモ全件を黙って採用しない。
`材料を追加`、各材料の全文表示、追加材料の選択解除を備える。中心の元本文は解除対象にしない。
中心を変更した時は新しい中心の元本文を材料に含める。以前の中心を材料に残すかは本人が選べる。
既存の「芽を見直す」では中心を固定する。新規作成中に、すでに芽の文があるメモを中心に選んだ場合はその文を示し、「既存の芽を見直す」か別の中心へ戻るかを選べる。入力中の案を下書きに残し、他の芽を黙って差し替えない。
材料の選択解除で一般のつながりは消えない。中心の選択は保存する芽の場所を決める操作であり、親を決める操作ではない。
単独の種から可能性が見えた場合も芽を作れる。栄養数やカテゴリ一致を解除条件にしない。

他の芽を材料にするときは「元のメモ」「芽の文」のどちらを使うか、引用する文と一緒に表示する。検索・カードで見ていた文を初期選択とし、別の文を勝手に保存しない。同じメモの両方を選ぶ場合も区別して表示する。内部では参照箇所とその文章を保存し、芽の材料をさらに再帰的に複製しない。

### 入力

複数の材料がある時の問い: **このメモを合わせると、どんなことができそう？**

中心の一件だけの時: **このメモから、どんなことができそう？**

補助文: `「なら、○○できるかも」のように、一言から。`
本文以外は任意。タイトル、タスク化、実行期限、細かな企画書を必須にしない。
材料は書きながら読み返せる。キーボードを開いても本文と保存操作が隠れない。
主ボタンは `芽として保存`、副操作は `あとで考える`。
単なる名前の変更や状態チップの切り替えを、ここでの芽化完了と扱わない。

### 保存と見直し

元のメモ本文、選んだ材料、新しく書いた芽の文を別々に保ち、同じ中心の育ちとして読めるようにする。
一覧と庭では芽の文を前面に表示できるが、`元のメモを見る` から原文へ戻れる。
既に芽の文がある中心では `芽を見直す` とし、その文を入力欄へ読み込んで明示的に保存する。公開前は現在の芽1件を保持し、全改稿履歴の管理は後の拡張とする。保存前のキャンセルと直後のUndoで意図しない変更を戻せる。
別の材料を足した時に、保存済みの芽の文を自動更新しない。必要な時に本人が見直す。
種に戻す操作でも原文・つながり・現在保存されている芽の文を消さない。まとめた考えとして残し、考えを寝かせてから再開できるようにする。
元のメモの変更・削除と、保存時に材料として見た言葉の扱いはデータ仕様に従い、現在と過去を混同しない。
`現在のつながり` と `この芽を作ったときの材料` を別の見出しで表示し、線と材料の履歴を区別する。
以前の芽で使った関係を外す時は `つながりを外しても、芽を作ったときの材料は残ります。` と添え、`材料を見直す` へ進める。
関係がない材料を並べる時は、接続済みであるかのような線を描かない。
既存データで状態だけが芽の場合も開ける。新たな可能性の文を勝手に生成して埋めない。

## 10. 庭と2,000件以上の整理

庭は、単なる種・芽・木の件数表から「どの言葉から何が育ったか」を見渡す場所へ進める。
主表示は、中心メモ・つながったメモの抜粋・芽の文を持つカード。件数は補助情報にする。
カードから局所マップへ入り、一覧へも戻れる。全件グラフを強制しない。

- 一覧と関係リストは可視範囲中心に描画し、2,000件以上を一度に画面へ積み上げない。
- 検索対象は全件。画面表示数と検索対象数を混同しない。
- つながりが多い中心には、全接続先の検索と件数を用意する。
- 最近触ったつながり、まだつないでいないメモ、保存した芽から別々に入り直せる。
- A-B-Cと連なることを理由に、全て同じ話題だと断定したり、一つの巨大な種へ統合したりしない。
- カテゴリで束ねる表示と、本人が結んだつながりを見た目・見出しで区別する。
- 語句・カテゴリの候補には実際の理由を添え、`違う` / `今はつながない` を選べる。
- 候補は手動接続の代わりにならない。候補がなくても検索から任意の2件をつなげられる。
- 自動分類・自動移動・全件の自動接続は行わない。整理のために記録を失わせない。
- 1件、50件、2,000件以上で同じ基本操作を使えるようにし、件数増加で操作の意味を変えない。

## 11. 任意の練習 — 一つの例を最後まで触る

初回の `例で使い方を見る` とヘルプから、同じ練習を開けるようにする。
実データとは別の領域を使い、検索・庭便り・通常の件数・バックアップに練習データを混ぜない。
途中で閉じられる。実際の記録がある人にも、練習を完了するまで操作を制限しない。

| 例のメモ | 内容 |
|---|---|
| A | 散歩写真が溜まる |
| B | 写真に短文を添えるのが好き |
| C | 離れた友人と近況を伝えたい |
| 芽の完成例 | 写真3枚とひと言で、友人に送る近況便りが作れそう |

1. AとBを選んで `2つをつなげる`。2件と線が見える。
2. `保存済みのメモをつなげる` からCを選び、Aとの関係が加わる様子を見る。
3. `ここから芽をつくる` で材料A・B・Cを読み、自分の案を書く。完成例を見ることもできる。
4. 保存後に芽の文と元の材料を読み、`自分のメモを書く` へ進める。

「3つ集めれば芽になる」という誤解を避け、例の最後に `数は決まっていません。できそうなことが見えた時に。` と添える。
初回の実利用では、保存・接続・芽化の直後に一度ずつ短い補助文を出す程度に留める。
操作説明のために自分の記録を勝手に増やしたり、見本の芽を本人の発見として保存したりしない。

## 12. 中断・間違い・失敗への画面契約

| 状態 | 画面で起こること |
|---|---|
| 入力中に戻る / 別タブへ移る | 本文・接続先・材料選択を下書きとして保持する |
| アプリを開き直す | 保存済みデータと復元可能な下書きを区別し、続きへ戻れる |
| 保存中 | 二重確定を防ぎ、成功と表示する前に永続化の結果を待つ |
| 保存失敗 | 本文と選択を保持し、消えないエラー表示と再試行を用意する |
| 関係を外す | `つながりを外す` と表示。メモ本文は残ることを示す |
| 元のメモが削除された | 別メモへ自動接続せず、削除済みであることと復元への入口を示す |
| もうつながっている | 重複作成せず、既存の関係を開く |
| 芽を考えている途中 | `あとで考える` で下書きを残し、材料へ戻れる |

芽の保存直後のUndoを新規昇格・見直しの両方に用意する。短時間のトーストを逃しても、常設の「種として考え直す」と「芽を見直す」から修正できるようにする。Undoは直前操作を戻し、後日の考え直しは文章を保つ別操作として扱う。
トーストは成功の補助表示。エラーや下書きの有無は、時間経過だけで見えなくしない。
背景で再会情報が更新されたり、別操作の保存が終わったりしても、編集中の本文を保存済みの古い本文へ戻さない。
破損データ等で変更を停止する場合も、読み出せる内容や書き出し・回復の入口を説明する。

## 13. 操作しやすさの共通条件

- 全主要操作をタップと読み上げで完結できる。ドラッグ、ピンチ、長押しだけの操作にしない。
- マップとリストで、中心、選択、接続済み、材料として採用中を同じ意味で伝える。
- 大きな文字でもボタンやカードの本文が重ならず、横スクロールなしで主要操作へ進める。
- 読み上げは「メモの短い内容、選択状態、つながり件数」を識別できるラベルにする。
- 画面を閉じた時は呼び出し元へフォーカスを戻し、中心変更や保存結果は短く知らせる。
- 色、線、ハプティクス、動きだけで保存成功や状態を伝えない。
- 動きを抑える設定では接続演出を省略できる。演出がなくても関係の変化が読める。
- 小さい画面とキーボード表示中でも、本文、接続先、確定操作を確認できる。

## 15. 2026-11-26 本人の実機フィードバックによる変更

本節は上の §1・§7・§9 と食い違う場合に優先する。

- 育ち方は **種 → 芽 → 花**。以前の「木」は表示名を「花」にする（保存上のキーは `tree` のまま）。
