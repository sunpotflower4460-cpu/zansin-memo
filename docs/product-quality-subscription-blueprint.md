# Product Quality & Subscription Blueprint

## 0. 結論

Kizashi Notes が勝つ場所は、汎用メモの機能数ではない。

> 書き捨てた断片が、時間をおいて意味を持ち、自分の創作や人生へ戻ってくる。

この循環を最も静かに、美しく、私的に実現する「思考の庭」を目指す。

現行MVPには、低圧入力・ローカル保存・再浮上・育成状態・変換・復元・バックアップという良い土台がある。一方、現状の価値は「保存できる便利なメモ」に近く、月ごとに支払う理由はまだ弱い。先に課金を実装するのではなく、日次・週次・月次で価値が深まる体験を作り、その後に同期・長期発見・AI補助を有料化する。

第一弾として、この設計と同じPRで **7日間の庭便り** のローカル版を実装する。これは課金機能そのものではなく、将来の有料価値を支える継続体験の核である。

---

## 1. 現行リポジトリ監査

### すでに強いもの

- タイトル不要・本文だけで保存できる低圧入力
- `SeedRepository` による保存層の分離
- 破損データの正規化、last-goodバックアップ、保存失敗時の変更ロック
- soft delete と復元
- 今日の種と説明可能な再浮上理由
- 種 / 芽 / 木 / 保管の成長状態
- 問い・行動・記事・プロジェクトへのローカル変換
- JSON / テキストのエクスポート
- Safe Area、キーボード、ハプティクス、アクセシビリティの基礎
- 型チェック・Lint・軽量テスト・CIの品質ゲート

### 購入前に埋めるべき差

| 優先 | 差 | 現在の影響 | 到達状態 |
|---|---|---|---|
| P0 | 継続価値が日次の「今日の種」1件に偏る | 数週間後に戻る理由が薄い | 日・週・月で異なる再発見がある |
| P0 | 長期の関連・変化が見えない | 種が増えるほど一覧へ戻る | テーマの重なりと変化が自然に浮かぶ |
| P0 | 同期・復旧が手動エクスポートのみ | 大切な記録を預ける安心が弱い | 暗号化同期と復旧が選べる |
| P1 | Homeに日常操作と設定・危険操作が混在 | 世界観と主要導線が途切れる | 日常の庭と設定を分離する |
| P1 | Gardenが状態別カード一覧に留まる | 「自分だけの庭」の驚きが弱い | 関係・時間・テーマの流れが見える |
| P1 | 変換結果が固定テンプレ | 数回で新鮮さが薄れる | 文脈を尊重した複数の育て方が返る |
| P2 | 音声・写真・共有拡張からの入力がない | 思いついた瞬間を逃しやすい | 3秒で種を置ける入口が増える |
| P2 | iOS固有体験が少ない | Expoアプリらしさが残る | Widget / Shortcuts / Share Extension が溶け込む |

### 直すべきではないもの

- 書く前の必須分類を増やさない
- ストリーク、赤いバッジ、罪悪感で継続させない
- AIにユーザーの心理状態を断定させない
- エクスポート・削除・プライバシーを課金壁の内側へ置かない
- SNSや公開フィードへ広げない
- 機能の多さをホーム画面に露出しない

## 2. プロダクトの中心体験

### North Star

**「保存数」ではなく「意味のある再会数」** を中心指標にする。

意味のある再会とは、過去の種を開いたあとに、次のいずれかが起きたこと。

- 本文を追記した
- 成長状態を変えた
- 別の種とつないだ
- 問い・作品案・小さな行動へ育てた
- その種から新しい種を書いた

### 価値の時間軸

| 時間 | 体験 | ユーザーが感じる価値 |
|---|---|---|
| 数秒 | ひとことを置く | 失わずに済んだ |
| 翌日 | 今日の種と再会 | 忘れていた言葉が戻った |
| 7日 | 庭便りを見る | 今週の自分の流れが見えた |
| 30日 | 月の地図を見る | 繰り返すテーマと変化に気づいた |
| 3か月 | 季節を振り返る | 断片が作品・企画・生き方へ育った |

この時間軸そのものが、継続利用とサブスクリプションの理由になる。

## 3. 追加する体験

### A. 7日間の庭便り — Free core / Plusで深化

週の終わりを強制せず、いつ開いても直近7日間を返す。

ローカル版:

- 新しく置いた種の数
- 過去の種を手入れした数
- 問い・行動・記事・プロジェクトへ育てた数
- 2件以上に重なったカテゴリ
- 断定しない短い振り返りの問い

Plus版:

- タグがなくても見つかる意味的なつながり
- 過去4〜12週との変化
- 「最近現れ始めたテーマ」「静かになったテーマ」
- 文章・音楽・企画など、育てたい方向別の提案
- ユーザーが採用・却下・書き換えできる庭便り

### B. Threads — 意味の水脈

種同士を「同じカテゴリだから」だけでなく、言葉・感情・時期・ユーザーの手動選択から関連づける。

- 最初はローカルの語句一致と手動リンク
- 次に端末上の埋め込み、または明示同意後のサーバー推論
- 関連理由を必ず表示する
- AIの関連は候補であり、確定しない
- 間違いを「違う」と教えられる

### C. Moon / Season Map — 長期の庭

分析ダッシュボードではなく、時間の流れを感じる地図にする。

- 30日: 今月の芽、繰り返す言葉、育った種
- 90日: 季節のテーマ、始まった流れ、完了ではなく落ち着いた流れ
- 1年: 作品・企画・問いへ育った系譜
- 数値は補助。主役は種とユーザーの言葉

### D. Capture everywhere — 気配を逃さない

- ホーム画面Widgetから1タップ入力
- Siri / App Intentsで「種を置く」
- Share ExtensionでWeb・写真・文章を種にする
- 音声入力と、原音を残すか消すかの選択
- オフライン時も必ず先にローカル保存

### E. Garden Studio — 創作へ育てる

汎用チャットを置かず、種から始まる小さな制作室にする。

- 問いを深める
- 歌詞・物語・記事の核を探す
- 企画の最小実験を作る
- 複数の種から構成案を作る
- AI出力より、引用した元の種を常に見える状態にする
- 生成物は別物として保存し、元の種を書き換えない

### F. Private Garden Sync — 預けられる安心

- ローカルファーストを維持
- 同期は任意
- 削除・エクスポートはいつでも可能
- 通信中・同期済み・競合を静かに可視化
- AI処理と同期を別の同意として扱う
- 将来の暗号化方式と復旧方法を先に設計してから実装する

## 4. Free / Plus 境界

無料版だけでも、アプリの約束を完全に果たす。Plusは保存を人質にせず、時間が生む価値を増幅する。

| 体験 | Free | Kizashi Plus |
|---|---|---|
| 種の作成・編集・検索 | 無制限・ローカル | 同じ |
| 今日の種 | あり | 選び方の調整・複数の再会 |
| 7日間の庭便り | 数とカテゴリによるローカル版 | 意味的関連・長期変化・育て方提案 |
| Garden | 状態・カテゴリ・手動関連 | 水脈・月・季節の地図 |
| 変換 | ローカルテンプレ | 文脈を読むStudio、月ごとの適正利用枠 |
| バックアップ | JSON / テキスト書き出し | 自動同期・復旧履歴 |
| 入力 | アプリ内テキスト | 音声・Widget・Share Extensionの高度機能 |
| データ権利 | エクスポート・全削除 | 同じ。課金状態に依存させない |

### 課金前に満たす条件

次のうち最低2つが本番品質になるまで、月額課金を開始しない。

1. 暗号化を含む自動同期・復旧
2. 長期の関連発見を行う庭便り / 月の地図
3. 継続利用に耐えるGarden Studio

それ以前は無料β、または買い切り相当の小さな支援プランの方が、ユーザーとの約束に誠実である。

## 5. 価格仮説

価格は事実ではなく、TestFlightとApp Storeで検証する仮説とする。

- 月額: **¥680**
- 年額: **¥5,800**（月あたり約¥483）
- 7日間無料体験: 初回起動ではなく、Plus機能を自分から開いた時に提示
- 単一のPlusプランから開始し、複数階層にしない
- AI利用量が原価を超える場合は、隠れた制限ではなく月内の目安を事前表示する

価格テスト候補:

- A: ¥580 / ¥4,800 — 初期普及重視
- B: ¥680 / ¥5,800 — 推奨開始点
- C: ¥880 / ¥7,200 — 同期とStudioが十分強い場合

見るべきなのは購入率だけでなく、90日継続率、庭便りの採用率、解約理由、AI原価を差し引いた粗利である。

## 6. Paywall UX

### 表示してよい瞬間

- 無料の庭便りを読み、「30日の流れを見る」を自分で押した時
- 関連候補を見て、「さらに水脈を探す」を押した時
- 自動同期をオンにしようとした時
- Studioの具体的な育て方を選んだ時

### 表示してはいけない瞬間

- 初回起動
- 最初の種を保存した直後
- 書いている途中
- エクスポート、復元、削除の途中
- エラー回復中
- 連続日数が切れた時

### Paywallに必要なもの

- 機能名ではなく、得られる変化を3つ以内で表示
- 年額を既定選択にしても、月額を同じ可読性で表示
- 復元、利用規約、プライバシー、閉じる操作
- 無料版で失われないものを明示
- AIに送信される範囲と同期される範囲を分けて説明
- 購入成功・保留・キャンセル・復元失敗の全状態

## 7. 画面情報設計

### Home — 今日の庭

1. 日付と短いブランドメッセージ
2. 今日の種
3. 「新しい種を書く」
4. 7日間の庭便り
5. 最近の種
6. 右上の設定ボタン

日常利用と設定を分ける。プライバシー、サポート、エクスポート、全削除はSettingsへ移す。

### Write — 3秒で置ける

- 起動直後から本文へフォーカスできる選択肢
- 詳細は折りたたみのまま
- 保存後は「完了」ではなく「庭に置きました」
- 自動下書き復元
- Plus機能を入力画面へ割り込ませない

### Garden — 自分だけの流れ

- 最初に庭の全景と今の重なり
- 次に種 / 芽 / 木
- その後にカテゴリ・水脈・時間
- 空の状態を4つ並べず、庭全体の一つの空状態にする
- 50件、500件、5000件で表示戦略を変える

### Settings — 信頼の場所

- 保存状態
- 同期とAI送信の個別設定
- エクスポート / インポート
- 最近削除した種
- 通知
- 購入管理 / 復元
- プライバシー / サポート / バージョン
- 全削除は最下部

## 8. 技術設計

### 境界を先に作る

```ts
interface EntitlementService {
  getSnapshot(): Promise<EntitlementSnapshot>;
  purchase(productId: string): Promise<PurchaseResult>;
  restore(): Promise<PurchaseResult>;
}

interface GardenInsightService {
  buildWeeklyLetter(seeds: Seed[]): Promise<GardenLetter>;
  findConnections(seeds: Seed[]): Promise<ConnectionSuggestion[]>;
}

interface SeedSyncService {
  push(changes: SeedChange[]): Promise<SyncResult>;
  pull(cursor?: string): Promise<SyncBatch>;
}
```

- UIはStoreKit、AIベンダー、同期先を直接参照しない
- `LocalGardenInsightService` を常に残す
- Entitlement取得失敗時に、無料の作成・閲覧を止めない
- AI失敗時も元の種とローカル変換を失わない
- 同期競合はlast-write-winsだけで本文を消さず、競合コピーを保持する

### 課金実装候補

Expo managed workflowのまま進める場合は、Development Buildに移行し、StoreKit 2を扱える購入ライブラリを導入する。初期運用の安全性を優先するならRevenueCat等でentitlementを抽象化できるが、SDK追加によるデータ収集範囲を審査前に確認する。

外部サービスのProduct ID、App Store Connect設定、秘密鍵が必要になるため、課金コードだけを先に入れない。次を固定してから専用PRで実装する。

- Product ID
- 月額 / 年額とOffering
- entitlement名
- 無料体験条件
- 購入・保留・取消・返金・復元の状態表
- Sandbox testerとTestFlight試験表
- プライバシーポリシーとApp Privacy回答

### AI実装原則

- APIキーをアプリへ埋め込まない
- ユーザーの種を学習利用しない契約・設定を選ぶ
- 送信前に対象範囲を表示できる設計
- 原文とAI生成物を別エンティティとして保持
- プロンプトインジェクションを含む外部取り込みデータを命令として扱わない
- コスト上限、タイムアウト、再試行、ローカルフォールバックを持つ

## 9. 実装ロードマップ

### Phase 5.1: Weekly Garden Letter Foundation — このPR

現行Phase 5（Gentle Resurfacing）を壊さずに深める小さな拡張として扱う。

- 直近7日の新規・手入れ・変換を純粋関数で集計
- 2件以上に重なるカテゴリを返す
- 断定しない振り返り文を生成
- Homeで今日の種の後に表示
- 書くCTAを設定群より前へ移動
- 新規依存、API、課金、認証は追加しない

### Proposed Phase 9: Home / Settings separation

- Settings画面を追加
- Homeからプライバシー・サポート・書き出し・全削除を移動
- 自動下書き復元
- Dynamic Type / VoiceOver / 小画面を実機検証

### Phase 10: Local relationship engine

- 手動関連づけUX
- 語句・カテゴリ・時間による説明可能な候補
- Garden全景と件数スケール対応
- 関連候補の採用 / 却下を保存

### Phase 11: Plus foundation

- `EntitlementService`
- Paywall状態設計
- StoreKit sandbox購入・復元
- 購入状態に依存しない無料コアの回帰テスト

### Phase 12: Sync & deep insights

- 認証、暗号化方針、同期競合、削除伝播
- サーバー側AIプロキシ
- Plus庭便り / 月の地図 / Studio
- コスト・プライバシー・障害時フォールバック試験

### Phase 13: App Store launch system

- 実機アクセシビリティ
- StoreKit全状態
- App Privacy / Privacy Manifest
- スクリーンショットとProduct Page Optimization
- TestFlightで価格・導線・継続率を検証

各Phaseは分離PRとし、現行 `AGENTS.md` の小さなPR原則を維持する。

## 10. 成功指標

### Activation

- 7日以内に3つ以上の種
- 過去の種を1回以上開く
- 1回以上、追記・関連・変換を行う

### Retention

- D7 / D30の再訪
- 7日間の庭便り閲覧率
- 意味のある再会率
- 30日以内に種が芽・木・出力へ育った割合

### Subscription

- Plus意図画面 → Paywall表示率
- Trial開始率 / Trial → Paid
- 月額と年額の構成
- 30 / 90 / 180日継続率
- 解約理由
- 有料ユーザー1人あたりAI・同期原価

### Guardrail

- 種保存完了までの時間
- 保存失敗、同期競合、データ復旧率
- AI提案の却下率
- 通知OFF率
- エクスポート成功率

ストリークや滞在時間はNorth Starにしない。このアプリの成功は、ユーザーを長く画面に留めることではなく、必要な言葉を未来へ渡すことである。

## 11. App Storeで伝える物語

1. **まとまっていなくても、種になる。** — Write
2. **忘れていた言葉が、今日戻ってくる。** — Home
3. **7日間の気配が、庭便りになる。** — Weekly Letter
4. **点だった思いつきに、水脈が見つかる。** — Garden / Plus
5. **あなたの言葉は、あなたのもの。** — Privacy / Sync

「AIメモ」ではなく「未来の自分と再会する思考の庭」として届ける。

## 12. このPRの非目標

- 実際のサブスクリプション購入
- Paywall
- 認証・クラウド同期
- 外部AI API
- 通知
- 新規ネイティブ依存
- Garden全体の再設計

これらは設計を固定したうえで、Proposed Phase 9以降の独立PRとして実装する。
