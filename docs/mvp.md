# MVP

## 公開前の中核体験 — 2026-11-26更新

初期MVPの土台を利用し、[中核設計](core-growth-loop.md)と[Phase 10.1〜10.6](core-growth-plan.md)を次の実装対象とする。以下は**追加設計であり未実装**。

1. なんとなく思ったことを、本文だけで種として残せる。
2. 別々に残した二つを後から探してつなげられる。分類・親子・方向を先に決めない。
3. 見ている種から新しくメモし、そのままつなげられる。
4. 実際のつながりを局所マップと等価リストで見られる。
5. 元の種と選んだ材料から「なら、こうできるかも」を書き、原文を残したまま芽にできる。
6. 量が増えても全件検索・任意カテゴリ・状態・つながりから探せ、元の場所へ戻れる。
7. 初回の任意の例、保存失敗時の保護、下書き、旧データ移行、関係を含む書出しが成立する。

芽になる件数条件・自動昇格・強制整理は入れない。自由な収集だけでも一回の利用は完了する。growthState選択や既存のテンプレ変換は土台として保持し、それだけを中核体験の完了条件にしない。

以下の項目は初期Phase 0〜8のMVP定義として残す。公開判断は上記と [受入条件](core-growth-plan.md)に従う。

## MVPの目的
Kizashi Notes の核となる体験（書く・残る・再会する・育てる）を、最小機能で検証すること。

## 必須機能
1. 種を書く
2. 種一覧を見る
3. 種の詳細を見る
4. 種に状態をつける（seed / sprout / tree / archived）
5. 種に気分・カテゴリ・重要度をつける
6. 今日の種をランダムまたはスコア順に1つ浮上させる
7. 種を「問い」「タスク」「記事案」「プロジェクト案」に変換するUI土台
8. ローカル保存または簡易DB保存を想定した設計

補足:
- UI上の「カテゴリ」は保存時に `tags` として扱う。

## 初期でやらないこと
- 複雑なAI連携
- ログイン必須化
- 課金
- SNS機能
- 重い3D表現
- 完全自動分類
- 複雑なグラフDB
- 過剰なアニメーション

## 成功条件
- 一言入力でも継続的に種を記録できる
- 数日後に過去の種と再会できる
- 種を次行動へ変換する導線がある
- UIが静かで低圧なまま成立している

## MVP完了チェックリスト
- [ ] Home / Write / Seeds / Seed Detail / Garden の最小画面がある
- [ ] Seed データモデルが一貫している
- [ ] ローカル保存で CRUD が成立する
- [ ] 状態・気分・カテゴリ・重要度が保存できる
- [ ] 再浮上ロジック（ランダム or スコア）が動作する
- [ ] 変換アクションUIの土台がある
- [ ] コンセプトから逸脱していない
