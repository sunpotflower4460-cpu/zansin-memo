# 種・つながり・芽のデータと保存契約

設計日: 2026-11-26。確認した実装: `ff0d8906ae2a07aa17da8492e5f342a2bfee6077`。
本書は設計であり、以下の型・保存方式・画面連携は未実装。

## 1. この設計で守ること

- なんとなく書いた一言も独立した `Seed` として残る。
- 後から「これとこれ、つながるかも」で結べる。親・子・栄養種別の選択を要求しない。
- 栄養は、ある種を考える材料としてメモを見るときの役割。別のメモ種別ではない。
- 芽は中心の種の ID と原文を保ち、別欄に保存した「なら、こうできそう」という考え。
- つながりを増やしても自動昇格しない。メモ数、日数、スコアによる昇格条件を設けない。
- 分類、候補推薦、AI、ネット接続がなくても、書く・つなぐ・芽にする一巡が成立する。

## 3. 正本となる最小モデル

### 3.1 メモとつながり

```ts
type SeedConnection = {
  id: string;
  aSeedId: string;
  bSeedId: string;
  origin: 'manual' | 'legacy';
  createdAt?: string; // legacyで不明な日時を作らない
  note?: string;      // 本人が任意で書く「つながりを感じたこと」
};

type SynthesisSource = {
  seedId: string;
  sourcePart: 'body' | 'synthesis';
  textSnapshot: string;
  titleSnapshot?: string;
  sourceUpdatedAt: string;
  sourceSynthesisId?: string; // sourcePart=synthesis の場合は必須
};

type SeedSynthesis = {
  id: string;
  statement: string;
  sources: SynthesisSource[];
  createdAt: string;
  updatedAt: string;
  promotedAt: string;
};

type SeedV2 = Omit<Seed, 'relatedSeedIds' | 'schemaVersion'> & {
  schemaVersion: 2;
  synthesis?: SeedSynthesis;
  /** 花（growthState: 'tree'）にしたときの記録。2026-11-26 追加 */
  bloom?: { note?: string; bloomedAt: string };
  /** 保管する前の育ち方。保管から戻すときに使う。2026-11-26 追加 */
  archivedFrom?: GrowthState;
};

type GardenStoreV2 = {
  storeVersion: 2;
  revision: number;
  lastMutationId?: string;
  seeds: SeedV2[];
  connections: SeedConnection[];
  drafts: Draft[];
};
```

`Seed` は現行型を指す。`transformOutputs`、既存の状態、日付、削除フラグ等は引き継ぐ。
`Draft` の契約は第8節。初回案内の既読状態は別のUI設定でもよく、意味データへ混ぜない。

### 3.2 一意性と表示のルール

1. 接続ペアを ID の昇順に正規化し、同じ二者には Connection を1件だけ持つ。
2. Connection ID は区切り文字の連結ではなく、正規化した ID 配列の JSON など衝突しない形から作る。
3. 自己接続は禁止。双方の Seed が存在することを保存時に確認する。
4. A側・B側のどちらで結んでも、両方の詳細に直ちに表示する。
5. `relatedSeedIds` が必要な既存画面には Connection から導出した読取用配列を渡す。
6. v2では `relatedSeedIds` を第二の正本として更新・永続化しない。
7. つながりの推移閉包を取って、連結成分全体を一つの種・テーマに自動統合しない。
8. 同じカテゴリは接続済みを意味しない。接続しても本文の複製・移動・統合は起きない。
9. 一つのメモが複数の中心や芽の材料になってよい。
10. 初回の芽は中心Seedごとに現在の1件を持つ。複数の別案・枝分かれは将来拡張。

### 3.3 芽の中心と材料

- 詳細から始めた場合は、現在開いているSeedが中心。
- 一覧で複数選んだ場合は最初に選んだSeedを中心候補として明示し、変更できる。
- 中心を改めて選ぶ操作を毎回強制しない。保存前には中心名と材料を確認できる。
- 既存の芽を見直すときは中心固定。新規作成中に既存芽のある中心へ変更した場合は、その芽を示して明示的に見直すか別中心へ戻る。作成中の案を下書きに残し、別の芽を黙って上書きしない。
- 材料は中心自身と、本人が選んだ0件以上の他のメモ。中心だけでも芽にできる。
- 中心自身の材料は原文 `body` に固定し、編集中の芽を自分自身の材料として引用しない。
- マップの中心は表示上の焦点であって親ではない。芽の保存前に「この芽は○○の種に残ります」と予告する。
- 関連候補や同じカテゴリを、本人の確認なしに材料へ含めない。
- 材料に使うこととConnectionを結ぶことは別。接続を追加するなら明示した別操作にする。
- 原文 `body` は芽の文章で上書きしない。芽の編集も原文の編集とは分ける。
- 他の芽を材料にする場合は「元のメモ」「芽の文章」のどちらを使うか、実際の文章とともに示す。芽を見て選んだのに原文だけを保存しない。
- 同じ他Seedの原文と芽を両方選んでもよい。材料の一意キーは `(seedId, sourcePart)`、メモ件数はSeed IDで重複除外する。
- `sources` は採用時に実際に読んだ文章を `textSnapshot` に固定する。材料のSeedや、その芽の `sources` 全体を再帰コピーしない。
- `sourceUpdatedAt` はbodyならSeed、synthesisなら芽自身の更新時刻。日時の形式を検証し、過去の材料日時を現在時刻で捏造しない。
- 新規採用時は指定部分が現在存在し、表示して確認した文章と一致するか検証する。出典が変化/消失していれば入力を保って再確認する。
- 「材料に更新あり」は選択した文章の差分と出典の有無で判定する。タグ変更等で更新日時が動いただけでは文章の変更と扱わない。
- 芽の文章だけを編集した場合、既存の材料スナップショットは保持する。材料の再選択/更新を本人が確認したときだけ採用内容を入れ替える。
- UIでは「芽をまとめた時のメモ」と「現在のメモ」を区別し、変化した材料には印を付ける。
- 既存の `sprout` / `tree` に芽の文章を捏造しない。「以前からの育ち状態」として保持する。

## 4. 保存コマンドと操作単位

UIが配列を直接書き換えて保存する経路を増やさず、アプリケーション層へ集約する。

| コマンド例 | ひとまとまりで確定する内容 |
| --- | --- |
| `captureSeed` | 新Seed作成、対応する入力下書きの消去 |
| `connectSeeds` | 一つの正規化ペアを作成。既存なら重複作成しない |
| `captureAndConnect` | 新Seedと中心とのConnection、入力下書きの消去 |
| `connectFromCenter` | プレビューした中心から各選択メモへの接続 |
| `disconnectSeeds` | 対象Connectionだけを除去。両方のSeedは保持 |
| `promoteToSprout` | 芽本文・材料スナップショット・`growthState`・下書き消去 |
| `updateSynthesis` | 現在の芽と確認済み材料を更新。原文は保持 |
| `softDeleteSeed` / `restoreSeed` | 削除状態だけを更新し、接続正本は維持 |

各コマンドは `commandId`、新規ID、時刻を最初の実行前に確定し、再試行で作り直さない。
同一 `commandId` の連打・再送を同じ操作として扱う。時間だけの700msガードに依存しない。
編集には対象の期待版/内容を含め、他の編集が先に確定したときに古い入力で上書きしない。
再起動後は下書きの予定生成IDと既存Seed/芽を照合する。最後のmutation IDだけで全履歴の重複排除ができるとは扱わない。
`connectFromCenter` は星形の接続を事前に見せる。選択した全員を相互接続する処理は禁止。
旧 `TransformOutput` は別の出力補助として残し、生成しただけでは芽や接続を増やさない。

## 5. 保存の成功・失敗・再試行

### 5.1 単一writer

- Seed、Connection、芽、下書きのv2 Envelopeは一つのwriterが順番に保存する。
- コマンドは最新の確定状態へ適用し、古いUIスナップショットを後から丸ごと書き戻さない。
- 書込み中の次操作はキューへ置く。永続化前の表示には「保存中」と示す。
- 主保存の完了確認前に「保存しました」「つなぎました」を出さず、入力欄を消さない。
- `lastResurfacedAt`、再浮上スコア等の背景書込みも同じwriterを通す。
- `revision` は主保存ごとに増やす。`lastMutationId` は保存したコマンドを識別する。
- 連続する同じ下書きの未着手保存だけは最新内容へまとめてよい。意味のある操作は間引かない。
- この契約は一つのアプリ実行環境内の順序保証。複数ブラウザタブの同時編集へ無条件に拡張しない。

### 5.2 下書き保存で入力を重くしない

- 入力中の文字は画面の編集状態へ即時反映し、全Envelopeの保存完了を待って文字を表示しない。
- 同じ下書きの待機中の保存をcoalesceし、未変更の内容を再保存しない。保存ボタン等の確定操作は優先してflushする。
- 下書き更新の購読と意味データの購読を分け、文字を入力するたびに全一覧・検索インデックス・接続インデックスを再生成しない。
- 下書きの材料はID・選択部分・照合に必要な版を保持する。各入力時に全材料本文や全Seedを下書きへ複製しない。
- 材料スナップショットは芽を確定/明示更新するときに必要分だけ作る。既存の固定スナップショットを毎回作り直さない。
- 2,000/5,000件だけでなく、長文・高次数・多材料の芽を含む条件でJSONのbyte数、serialize/parse時間、保存時間、入力応答を測る。
- 全Envelope保存で目標を満たせない場合は、まず保存頻度・購読・重複データを見直す。内容の切捨てや入力の強制上限で隠さず、DB導入をこのPhaseの前提にしない。

### 5.3 コミット点

主保存キーへの書込みが確定点。主保存とlastGoodはトランザクションと呼ばない。

| 結果 | 扱い |
| --- | --- |
| 主保存・lastGoodとも成功 | 保存成功。下書き消去を含む確定状態を表示 |
| 主保存成功・lastGood失敗 | 保存成功とバックアップ更新失敗を区別。操作全体を再実行しない |
| 主保存失敗 | 未確定の入力とコマンドを保持。成功通知を出さず再試行を用意 |
| 応答不明・途中終了 | 読み直してrevision / mutation ID /生成IDを照合してから再試行 |
| 読込失敗・未知スキーマ | 自動保存を止め、空配列で上書きしない |

主保存の状態が不明な間は後続の意味データ操作を確定しない。
再試行は同じIDを含む同じ操作で行い、メモ・接続・芽を二重に増やさない。
バックアップを更新し直す場合も、古いバックアップ処理が新しい版を上書きしないよう直列化する。
OSによる終了直前の未確定入力まで保存を保証するとは表示しない。

## 6. v1からの非破壊移行

現行キー: `kizashi-notes:seeds:v1` / `kizashi-notes:seeds:v1:lastGood`。
新しい主保存キー案: `kizashi-notes:garden:v2`。lastGoodもv2専用にする。

1. 有効なv2があれば、それを読む。v1へ戻して取り込み直さない。
2. v2が存在するが壊れている場合はv2のlastGoodを確認。v1を最新データとして黙って復元しない。
3. v2未作成時だけv1を読み、元の文字列を変更せず残す。移行前原本を保持できなければ移行を中止する。
4. 配列、Seed ID、本文、版を検証。未知の新しい版を現行normalizerへ通さない。
5. 同じIDが複数ある等、対応先を一意に決められない場合は止め、原本を保存して回復手段を示す。
6. 全Seedの `relatedSeedIds` を走査し、どちら側にだけ記録されていても同じ無向ペアへまとめる。
7. これらは `origin: 'legacy'` とし「以前からのつながり」と表示。栄養の方向や芽の材料を推測しない。
8. 旧関連の作成日時は不明なので空にする。移行日を関連した日として表示・集計しない。
9. 自己参照・存在しないIDは可視接続にしない。原本と診断に残し、問題を黙って削除したことにしない。
10. 削除済みSeedが存在するなら、そのSeedへの接続も保持する。復元で戻せるようにする。
11. 旧 `transformOutputs` と `sprout` / `tree` / `archived`、日付、本文を引き継ぐ。芽の文章は新規作成しない。
12. v2全体を検証してから新キーへ保存し、読み直して件数・ID・本文・接続を照合する。
13. 移行途中で終了しても再実行できるよう、ConnectionのIDとペア正規化は決定的にする。
14. 成功後もv1原本を自動削除しない。ただし本人の「全データ削除」では旧版も削除対象に含める。

`normalizeSeed` は現在、定義した項目以外を落とす。v2をv1型へ通してから保存する経路は作らない。
新しい型、読込、保存、エクスポートの対応を同じ基盤Phaseでそろえる。
古いアプリを同じデータへ戻すことは逆移行ではない。新版作成後の情報を失うロールバックを避ける。
ただし起動時は、次節の削除中markerの確認を通常読込・バックアップ回復・v1移行より先に行う。

## 7. 解除・削除・編集・昇格を戻すとき

| 操作 | 保持するもの / 表示 |
| --- | --- |
| つながりを外す | 両方のメモ、他の接続、既にまとめた芽とその材料を保持 |
| 芽の材料から外す | 現在の芽の材料リストだけを変更。接続は自動解除しない |
| 材料メモを編集 | 芽の文章と保存時スナップショットは変えず「材料に更新あり」 |
| 材料メモを削除 | 接続とスナップショットは復元用に保持。通常表示では削除済み本文を露出しない |
| 削除メモを復元 | 双方が有効なら接続表示を戻す。芽の文章を再生成しない |
| 中心メモを削除 | 中心と芽は最近削除へ。材料や他の芽は連鎖削除しない |
| アーカイブ | 既存状態を尊重。通常の提案から外し、既存接続と芽を保持 |
| 全データ削除 | 原文、接続、芽のスナップショット、下書き、v1原本、lastGood、破損退避を対象にする |

接続解除と材料除去は同じ操作にしない。既に芽に使われていれば、そのことを短く説明する。
文言は「つながりを外しても、芽を作ったときの材料は残ります」。続けて「芽の材料を見直す」へ進める。
削除済み材料は「元のメモは最近削除にあります」と表示し、復元後に内容を再表示する。
本人が書いた芽の文章自体は、材料の削除を理由に勝手に削らない。
個別の永久削除は今回追加しない。全データ削除だけは、スナップショットを含む実データ全体を削除する。

**芽の保存直後の「元に戻す」** は新規昇格・見直しのどちらも公開前必須の短時間の便利導線。保存済み操作の逆操作として、以前の成長状態と芽へ戻す。
書いた新しい文章は下書きとして残す。途中に別編集があれば全体スナップショットを巻き戻さず、対象を確認する。
**後日の「種として考え直す」** は成長状態を `seed` へ戻し、まとめた考えと材料を残す。
そのときは現在の芽として数えず、詳細から以前の考えを読み直し、再採用・編集できる。
短時間のUndoを逃しても常設操作から修正できる。この二つを同じ処理名で曖昧にしない。
Undoに必要な直前の逆操作情報は保持するが、全revisionの履歴保存や閲覧UIは今回追加しない。

### 全データ削除の中断と再開

キーを消すだけでは、保存中のwriterや次回起動のv1移行で古い内容が復活し得る。削除を専用の保守操作として扱う。

1. 新しい保存コマンドの受付を止め、専用キーへ削除中marker（世代IDと開始日時だけ。本文なし）を永続化する。marker保存に失敗したら削除を開始しない。
2. 進行中の書込み終了を待ち、未着手キューとdebounceタイマーを破棄する。旧世代のコールバックが保存を再開できないよう世代を照合する。
3. このアプリの主保存・lastGood・v1原本・移行退避・破損退避・下書きの各キーを削除する。他アプリのキーまで一括削除しない。
4. 内容が空の有効なv2 Envelopeと空のv2 lastGoodを確定し、残した旧版/退避キーがないことを確認する。
5. メモリ上のデータ、下書き、選択、キャッシュ、Undo情報を空にし、markerを解消して新世代のwriterを再開する。
6. 途中失敗ではmarkerと削除未完了表示を残す。次回起動はmarkerを最優先で読み、通常の読込・回復・v1再移行を行わず、この削除手順を再開する。

終了直前の失敗も含め、marker解消と対象データ消去を確認できるまでは「すべて削除しました」と表示しない。
完了後の空v2は初期化済みの記録でもあり、残存した旧データを新規移行する理由にしない。
markerの読込み自体に失敗した場合も通常の初期化へ進まず、変更を止めて再試行する。

## 8. 下書きと編集中の内容

最小の `Draft` は ID、用途、対象Seed ID、本文等の入力値、最終保存日時を持つ。
用途は新規メモ、原文編集、中心への新規メモ、芽編集を区別する。
新規メモのIDと芽のIDは下書きに保持し、復元・再試行で作り直さない。

- 編集セッションを対象IDごとに保持し、Seedオブジェクトの参照が変わっただけで初期化しない。
- 背景再浮上、関連追加、変換、他の画面の保存が編集中本文を置き換えない。
- 下書きは短いdebounceでwriterへ渡し、画面離脱・バックグラウンド移行時に可能な範囲でflushする。
- メモ保存または芽保存と、その下書きの消去は同じEnvelope更新で行う。
- ストレージエラー中も入力をメモリに残し、「保存済み」と誤認させない。
- 原文が別操作で変わった場合は入力を退避し、暗黙に上書きしない。
- 芽の材料が編集中に変わった場合は保存前に再確認。削除済み材料を新規採用しない。
- キャンセルは本人の入力を消す意味にしない。明示した「下書きを破棄」だけが破棄操作。
- 下書きの自動保存は、種の新規件数・手入れ・庭便りの育成実績に数えない。

## 9. 検索・局所マップ・多数の種

- 書いた種の一覧を正本とし、リンクしたためにどこかへ移動して見失う状態を作らない。
- 本文・任意タイトルの検索、最近の順、つながりあり/なしから探せる。カテゴリは任意の補助。
- 確定した芽の文章も検索対象にする。過去材料のスナップショット・削除済み本文は通常検索へ混ぜない。
- リンク選択は全件検索できる。先頭20件だけで選択肢を打ち切らない。
- 必須の局所マップは中心と直接つながる1-hopだけ。循環があっても再帰展開しない。
- 本文を読めるカード/接続リストを同時に用意し、線や位置だけを情報源にしない。
- ノードを選ぶとその種を新しい中心にでき、戻ると前の中心とスクロール位置へ戻れる。
- 接続が多い中心では検索・ページング/段階表示を使い、省略件数と全件への入口を示す。
- 削除・保管を通常候補へ再推薦しない。既存接続の表示は削除と保管を区別する。
- `Map<SeedId, Seed>` と隣接インデックスをEnvelopeの確定版から導出し、二重保存しない。
- 候補推薦は実接続から分け、採用時だけ Connection を作る。候補を線で接続済みに見せない。
- 一致語・カテゴリは候補の根拠を表示できる場合だけ使う。時間や気分だけで意味的関連を断定しない。
- Phase 10.5の「今はつながない」は正規化ペアをローカルの推薦設定へ保存し、そのペアを次回起動後も候補から外す。手動検索・接続は妨げず、「見送った候補を戻す」で解除できる。UI設定として保持してもよいが、全データ削除の対象キーへ含める。

## 10. 庭便りと書き出し

- 育成の表示は新しい種、本人が結んだつながり、本人がまとめた芽を区別する。
- 閲覧、検索、再浮上、下書き保存、移行、候補提示は育成実績を増やさない。
- legacy接続の日時を推測せず、今週の新しい接続に数えない。
- 接続数は正規化ペア単位。双方の詳細に表示されることを2件と数えない。
- 芽数は現在 `sprout` / `tree` のSeedで確定したsynthesisを基準とし、旧状態だけのものとは表示を分ける。
- `promotedAt` は本人による芽の採用時刻。単なる芽本文編集で更新しない。
- 今週の接続の表示は現在残っている接続の件数であると定義し、過去の解除も含む活動履歴と混同しない。
- 汎用イベントソーシングは導入しない。現時点では作成・接続・芽の各日時から履歴表示を作る。
- JSONはstore/export版、全Seed、接続、芽と材料、下書きを含む全データ書出しにする。「削除済み・下書きも含む」と実行前に明示する。
- 通常のテキスト書出しは非削除Seedと中心名、芽、材料、接続先を対象にし、削除済み材料の本文は出さない。JSONと収録範囲が異なることを明示する。
- JSON書出しだけを「取り込みで復元できる」と案内しない。復元対応をうたうには読込経路も別途必要。
- 全件削除は各キーの削除完了を確認し、失敗時に完了と通知しない。

## 11. 実装単位と受入条件

既存のPhase 1〜8を作り直さず、Phase 10の拡張として小さく進める。
Phase 9の下書き計画と重複する部分は、本書の下書き契約へ統合する。

| Phase | 範囲 | 完了条件 |
| --- | --- | --- |
| 10.1 | v2保存・移行・正規化・単一writer・書出し | v1原文と全関連を保持し、失敗/再試行で二重化しない |
| 10.2 | 最短入力・後からつなぐ・中心へのメモ・下書き・1-hop可視化 | 未分類のメモを検索して結び、双方から見られ、再起動後も残る |
| 10.3 | 芽の中心/材料確認・本文保存・編集・戻す | 原文を保って芽にでき、由来をたどれる |
| 10.4 | 初回体験・例・空状態・文言 | 初見で書く/結ぶ/芽にする意味を理解して自力で操作できる |
| 10.5 | 説明可能な候補・多数件整理・局所マップの段階表示 | 候補と確定接続を混同せず、大量でも過去メモを探せる |
| 10.6 | 一巡検証・実機・アクセシビリティ・公開判断 | 下記の重要シナリオを確認し、未確認を明記 |

### 必須の検証シナリオ

1. タイトル/タグなしで3つ書く → 日を置いて検索 → AとBを結ぶ → CをAに結ぶ → Aを中心に芽を書く。
2. BからAへの接続も見える。CとBの接続は勝手にできない。Aの原文は芽保存後も同一。
3. 21件目以降のメモを探して結べる。0/1/20/21/200/2,000件で探索・遷移・入力を確認する。
4. A-Bだけ解除して、B本文・A-C・芽の材料が残ることを確認する。
5. 材料を編集/削除/復元し、芽の意味と原文、接続が意図せず変化しない。
6. 関連の片側のみ/両側/重複/自己参照/削除対象/未知対象を含むv1移行fixtureを使う。
7. 既存のsprout/tree/変換結果を保持し、合成した文章や移行日の育成履歴を捏造しない。
8. 主保存失敗、主保存成功後のlastGood失敗、古い保存完了、二連打、終了後再開を注入する。
9. 新メモと接続、芽と状態が半分だけ確定したUIにならない。再試行しても各1件。
10. 未保存の原文編集 → 関連操作/変換/背景更新でも入力が消えず、保存済み本文へ勝手に戻らない。
11. 未知版と壊れたv2では空のv1状態で上書きしない。v1原本を残し、JSONに全関係が含まれる。
12. 昇格Undoと後日の「種として考え直す」を区別し、他操作の成果を巻き戻さない。
13. VoiceOverで中心・接続先・候補/確定・材料を識別でき、線を見なくても一巡できる。
14. 全データ削除後に旧版・lastGood・下書き・材料スナップショットから内容が復活しない。
15. 別の芽の文章を材料に選び、原文との区別・実際に選んだ引用・再帰コピーしないことを確認する。
16. writer実行中の全削除、削除の各段階で終了、marker読込失敗でも、再起動時に削除再開を優先し旧内容を復活させない。

単体試験は正規化/移行/コマンド/保存失敗へ、画面試験は一巡と下書き保護へ絞る。
実装後の基準は既存 `npm run check` と上記の必要な統合・実機確認。設計追加だけではアプリ実機検証済みとしない。
