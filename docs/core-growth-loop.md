# 公開前の中核設計 — 思いつきを残し、つなげ、芽に育てる

更新日: 2026-11-26（日本時間）

状態: **設計確定・実装は未着手**。この文書の追加は、以下の機能が実装済み／実機検証済みであることを意味しない。

## 1. 今回の依頼と、この設計の役割

ユーザーが最も機能させたい体験は、次の一周である。

> なんとなく思ったことを、種として残す。後日、別々に残した思いつきに「つながるかも」と感じたら結ぶ。つながりを眺め、気づきを足し、「なら、こんなことができそう」を自分の言葉で芽にする。

大量に残しても、探す・見返す・つながりをたどる場所がわかることまでを、公開前の中核に含める。

本書は既存の「低圧で書ける・再会できる・育てられる」を具体化する。記録の目的を創作・仕事だけに狭めず、感情、違和感、疑問、日々の観察も同じように扱う。収集だけの日、つながらない種、結論の出ない考えも完成した利用である。

### 読む順番

| 文書 | 決めること |
|---|---|
| 本書 | 体験の約束、用語、現状との差、優先順位 |
| [画面・導線・文言](core-growth-ux.md) | 入力、後からつなぐ、図で見る、芽化、大量の探索 |
| [データ・保存契約](core-growth-data.md) | 接続と芽の正本、互換移行、下書き、保存失敗、削除 |
| [実装順・検証・公開判定](core-growth-plan.md) | Phase 10.1〜10.6、対象ファイル、受入条件 |
| [実装担当へのスタートプロンプト](core-growth-start-prompt.md) | そのまま渡す短い依頼文 |

既存 Phase 0〜8 は初期土台として残す。今回の実装対象は、既存の [品質・継続設計](product-quality-subscription-blueprint.md) の Phase 10（Local relationship engine）を具体化した Phase 10.1〜10.6。新旧で中核体験の詳細が異なる場合、この文書群を使う。課金・同期・外部AI・公開作業まで承認したものではない。

## 2. アプリの約束を、一文と三つの操作で伝える

**思いつきを残して、つなげて、できそうなことに育てる。**

操作は「メモを書く」「つなげる」「芽にする」。初回から木・森・水脈・重要度・成長率を覚えなくてよい。

| 言葉 | 意味 | 誤解させないこと |
|---|---|---|
| 種 | 保存した思いつきや気持ち。短く、曖昧でよい | 良いアイデア、タイトル、分類を要求しない |
| つながり | 本人が「一緒に考えたい」と結んだ二つのメモ | 同じカテゴリ、賛同、事実の裏付けとは限らない |
| 栄養 | ある種を考えるときに、材料となる別のメモ | 入力時のメモ種別ではない。親子関係や移動でもない |
| 芽 | 材料から本人が言葉にした、新しい可能性・問い・方向 | 件数やAIスコアで自動昇格するものではない |

同じメモが複数の種の栄養になってよい。反対の気づき、制約、違和感もつなげられる。つないだだけで本文は合体しない。

「昇格」は開発側の説明に限定し、利用画面では「芽にする」「芽を見直す」とする。成果や能力の評価を連想させる点数、レベル、完成率は置かない。

### 木・保管との関係

- 既存の `tree` と `archived` を削除・強制変換しない。既存データは閲覧・検索・編集できる。
- 新しい初回体験は種と芽までで成立させる。木の新しい昇格条件は今回追加しない。
- 以前に状態だけで芽・木にした記録に、合成文や由来を捏造しない。
- 保管は整理上の置き方であり、失敗・枯死・降格と表現しない。

## 3. 価値が生まれる一続きの例

これは説明・練習用の架空データである。ユーザーの記録には混ぜない。

| 時点 | 残したこと／したこと | 画面でわかる変化 |
|---|---|---|
| 初日 | 散歩で撮った写真が、スマホにたまるばかり | 一つの種として残る。次の操作は要求されない |
| 別の日 | 写真に短い言葉を添えるのが好き | 独立した種として残る |
| さらに別の日 | 離れた友人と、近況を伝え合いたい | 独立した種として残る |
| 見返した日 | 写真の種と、短文の種をつなぐ。友人の種も選ぶ | 中心の種と、結んだ二つのメモが線とカードで見える |
| 考えが生まれた時 | 写真3枚にひと言を添えた、小さな近況便りを作れそう | 同じ種の上に「できそうなこと」が芽として残る |
| 次に思いついた日 | 紙のカードで送るのも楽しそう | 新しい種を追加できる。既存の芽は勝手に書き換わらない |

芽は元メモの要約だけではない。材料を見た本人の、新しい見方が一文増えることが価値である。ただし、アプリが文章を採点して芽の資格を判定してはならない。

## 4. 二つの育ち方を、同じ仕組みで支える

### A. 最初はばらばら、後からつながる

1. 何も決めず、思ったことを何個でも残す。
2. 一覧・検索・再会した種から、二つを選んでつなぐ。
3. つながりを図またはリストで見て、別の材料も足す。
4. 中心に見ている種から芽を書く。

これを第一級の使い方にする。書く時点で「どの種の栄養か」を選ばなくても、何も取りこぼさない。

### B. 一つの種を見ながら、思いつきを足す

1. 種の詳細で「メモを足す」を選ぶ。
2. 一言書き、「保存してつなぐ」。
3. 元の種に戻ると、追加したメモとつながりが見える。

接続先はすでに本人が選んでいるので、再選択させない。どちらの経路でも保存されるメモと接続は同じ種類のデータになる。

## 5. つなぐことと、まとめることを分ける

### つながり

- 「一緒に考えたい」という仮の関係でよい。理由は任意。
- AとBの関係はどちらからでもたどれる。親・子・主・従の指定は不要。
- 二つの種をつなぐとき、カテゴリや題名の一致は不要。
- 中心から複数の種を結ぶ場合、保存前にどの線を追加するか示す。選んだ全メモ同士を勝手に結ばない。
- A–B、B–Cがあっても、A–Cを接続済みにしない。つながった集団全体を「同じテーマ」と自動断定しない。
- 解除しても、両方のメモと他のつながりは残る。

### 芽

- 一文の可能性・問い・方向と、本人が選んだ材料を一緒に保存する。
- 現在中心に見ている種のIDと元本文を維持し、別の欄に芽の文章を保存する。
- 一覧で複数を選んだ場合、最初に選んだ種を中心候補として見せ、変更できる。中心の再選択を必須にはしない。
- 材料として採用する言葉を本人が確認する。接続していないメモも材料に選べるが、線は自動追加しない。選んでいない隣接メモまで芽の根拠に含めない。
- 他の芽を材料にするときも、原文と芽の文のどちらを読んで選んだかを残す。見ていた文章が別の文章に置き換わらないようにする。
- 栄養が0件でも、本人が可能性を思いついたなら芽を作れる。件数・日数の解禁条件は設けない。
- 芽にしても元の種・材料は消費されない。別の考えにも使える。
- 保存を閉じれば下書きとして残る。芽を戻しても元本文・接続を失わない。

「つなぐ → 意味を考える → 自分の言葉を残す」が、状態バッジ変更だけで終わらないこと。

## 6. 視覚化は、今考えている範囲を見せる

公開前に、接続した二つのメモを実際に線で確認できる軽量な表示を入れる。状態ごとの件数やカテゴリだけを「つながりの可視化」と呼ばない。

- 中心の種と直接つながる種を表示する。本文の短い見出し、状態、接続理由を必要に応じて読める。
- タップで中心を移す。パン・ピンチ・ドラッグを使わなくても、全ての操作を完了できる。
- 「戻る」で直前の中心・一覧条件・スクロール位置に戻れる。
- 多いときは一部を表示し、「ほか○件」から全件リストへ。隠れている数を明示する。
- つながりのない種も単独カードとして存在する。寂しい、未完成、要整理と評価しない。
- 同じ接続をリストでも確認・操作できる。色と線だけで状態を伝えない。
- 全件を一画面の巨大グラフへ押し込めない。地図全体の探索が必須になるUIは採用しない。

基本の図は Phase 10.2、件数の多い表示と候補は 10.5。視覚化を公開後まで延期しない。

## 7. たくさん溜まっても迷わない、四つの入口

| 入口 | 役割 | 守ること |
|---|---|---|
| すべてのメモ | 記録の所在を確かめ、時系列で見る | 一つのSeedは一件。接続数や材料コピーで件数を水増ししない |
| 検索・任意カテゴリ | 言葉、期間、状態、カテゴリから探す | 本文・題名・芽の文章を検索。カテゴリ未設定でも使える |
| つながり | 今気になる種の周囲をたどる | 行き止まりや戻り先の喪失を作らない |
| 芽 | 生まれた可能性と、その材料を見返す | 芽の文章から元メモに戻れる |

「まだつながりのないメモ」は任意の絞り込み。処理すべき受信箱にしない。カテゴリは複数可、後から付ける補助であり、フォルダ移動や所属の強制にしない。

関連候補は補助として最大少数件を表示し、全件検索を必ず残す。共通する語やカテゴリなど、実際に使った理由を示す。似ている語を含むことと、本人がつなぎたいことを同一視しない。

## 9. 公開前に含めること／後の拡張

| 公開前の必須 | 後で検討できる拡張 |
|---|---|
| 本文だけの保存、復帰可能な下書き | 音声・写真・Widget・共有拡張 |
| 後から任意の二つをつなぐ／外す | 埋め込みによる意味検索・外部AI候補 |
| 新しく書き、見ている種につなぐ | AIによる芽の下書き |
| 局所図と同等に使えるリスト | 巨大グラフ、3Dの森 |
| 材料を読んで、自分の芽を書き残す | 一つの種から複数の芽を管理する枝分かれ |
| 全件検索・任意カテゴリ・戻り位置維持 | 月／季節の地図、共有・共同編集 |
| 移行・保存失敗・解除・削除・書出しの整合 | 同期、課金、アカウント |
| 省略・再体験できる短い説明例 | 追加の世界観用語・長い演出 |

候補精度を高める前に、候補を使わず本人が確実につなげられることを完成させる。無課金・オフラインで中核の一周を完了できることを維持する。

## 10. 設計の判断基準と参照資料

採用した理由は、本アプリの目的に照らした設計判断であり、効果を実証済みとするものではない。

- Appleの[オンボーディング](https://developer.apple.com/jp/design/human-interface-guidelines/onboarding)は、短く省略可能な学習と、操作の文脈に沿う説明を推奨する。ここでは任意の例と、その場の一文説明に適用した。
- W3Cの[Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)をWeb版の参照にし、接続をタップでも完了できる設計にする。ネイティブ版にも同じ操作上の配慮を適用する。
- W3Cの[Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)をWeb版の保存・接続結果の通知に適用する。iOSではVoiceOverの読み上げを別途実機確認する。
- 元の理念・非目標は [concept](concept.md)、[non-goals](non-goals.md)。現在の実装事実は上の監査表のリポジトリ内ソースを参照する。
