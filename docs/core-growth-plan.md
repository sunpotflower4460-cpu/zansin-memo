状態: **実装担当への設計契約**。以下のチェックは未実施・未合格。コード実装やユーザーテストの結果を先取りしない。

前提は [中核設計](core-growth-loop.md)、[UX仕様](core-growth-ux.md)、[データ契約](core-growth-data.md)。監査基準は `ff0d8906ae2a07aa17da8492e5f342a2bfee6077`。

## 1. 既存Phaseとの関係

Phase 0〜8 の画面・CRUD・再浮上・Transform・Gardenは土台として利用する。作り直しや、古い Issue 1 からの再実装はしない。

今回の Phase 10.1〜10.6 は、[既存blueprint](product-quality-subscription-blueprint.md) の Phase 10（Local relationship engine）を、最新のユーザー依頼に沿って具体化したもの。公開前の優先は次の順序に更新する。

| 順序 | 実施内容 | 既存計画との関係 |
|---|---|---|
| 1 | Phase 10.1 保存契約と互換データ | 関連・合成を安全に保存する前提 |
| 2 | Phase 10.2 書く・後からつなぐ・図で見る | 手動関連を主導線へ。Phase 9 の下書き復元を必要範囲だけ前倒し |
| 3 | Phase 10.3 材料から芽を書く | 既存Phase 6の出力形式変換と区別する |
| 4 | Phase 10.4 初回理解・再開 | 実在する操作の上に、任意の説明例を追加 |
| 5 | Phase 10.5 大量の整理・候補・再会 | 大量でも全件到達できることを完成 |
| 6 | Phase 10.6 統合検証・実機・初見検証 | 公開判断に必要な証拠を集める |

Phase 9 の Settings 全面分離は独立して進められるが、この一周を完成させる前提にしない。Phase 11/12 の課金・同期・外部AIは今回に含めない。App Store提出や本番デプロイは別の依頼として扱う。

各Phaseは小さなPR単位で進める。1Phaseが大きければ同じ契約内で複数PRに分割する。PRには「対象Phase・変更・未実装・確認結果・次Phase」を記す。

## 2. Phase 10.1 — 保存契約・互換データ

### 到達状態

保存済みと伝えた思いつき、接続、芽の材料が、再起動後も同じ意味で残る。旧データを壊さず、後続画面が利用できる境界を作る。

### 対象ファイル

- `src/domain/types.ts`
- `src/data/seedRepository.ts`
- `src/data/asyncStorageSeedRepository.ts`
- `src/utils/saveState.ts`, `src/utils/exportFormat.ts`
- `App.tsx` の保存調整部分
- 対応する既存テスト。必要なら保存コーディネーターを小さく分離する。

### 実装すること

1. [データ契約](core-growth-data.md) のv2スナップショット、無向Connection、別欄のSynthesisを定義する。
2. `relatedSeedIds` を一般の接続へ安全に移行する。自己参照・重複・不存在参照・片方向・循環を扱う。
3. 書込みを一つの経路に直列化し、世代が古い保存で新しい内容を上書きしない。
4. 本保存成功と補助バックアップ失敗を区別する。再試行は同じ操作・同じIDで行う。
5. 保存が成功するまで入力や対象を失わず、成功通知を先行させない。
6. JSONとテキストの書出しに接続・芽・材料の意味を含める。

### 完了条件

- 旧fixture読込→v2保存→再読込で、本文・状態・変換出力・削除状態を維持。
- 接続をどちらから見ても同じ一つの関係として扱える。
- 書込み遅延・失敗・連打・再試行を注入して、新しい保存の巻き戻りや二重作成がない。
- 読込失敗・不明な将来schemaを空データとして上書きしない。
- 原文・接続・芽が書き出せる。復元インポートUIを新設せず、正規化往復の試験でデータ契約を確認する。

### このPhaseでしないこと

大規模な画面改修、候補推薦、外部AI、クラウド同期、DBライブラリ追加。

## 3. Phase 10.2 — 自由に残す・後からつなぐ・図で見る

### 到達状態

先にばらばらの種を残し、あとで二つを選んで結べる。結果が図と読めるリストの両方に表れる。

### 対象ファイル

`App.tsx`, `WriteScreen.tsx`, `SeedsScreen.tsx`, `SeedDetailScreen.tsx`, `GardenScreen.tsx`。新しい接続選択・局所マップ・等価リストは必要な単位でコンポーネント分離する。

### 実装すること

- 本文だけで新しい種を保存。初期状態はseed、メタデータは任意の詳細に収める。
- 通常保存の後に「つなげる」を任意表示。保存の条件にはしない。
- 一覧で二つを選択して接続。詳細から全件検索して既存メモを接続。
- 詳細から新しくメモして、その種へ接続。本保存の一つのスナップショット更新で両方を確定し、補助バックアップの結果と区別する。
- 同一ペアの二重接続防止、自己接続禁止、解除・やり直し・削除との区別。
- 中心＋直接のつながりを示す局所マップと、全接続を読める等価リスト。
- 新規／追記／芽／本文編集の下書きが別の操作で上書きされない保存境界。
- 戻る先、一覧の検索・絞り込み・スクロール、図の焦点を保持。

### 完了条件

- タイトル・カテゴリ・接続先を決めず、三つのメモを独立して残せる。
- 二つを選んでつなぎ、どちら側からも相手を見つけられる。選択に長押しを必須としない。
- A–BとB–Cを作っても、A–Cの線が勝手に増えない。
- Aを見てBを書いた場合、Aを再選択せず保存・接続が完了する。
- 線を外しても両方のメモが残り、後から再接続できる。
- 先頭20件にない古いメモも検索して接続できる。
- 図のタップとリスト操作のどちらでも、同じ関係・詳細・戻るを利用できる。
- 下書きはタブ切替・戻る・アプリ再起動から復元できる。未保存中の再浮上更新で巻き戻らない。

基本の可視化はこのPhaseの必須。Phase 10.5まで線の見えない接続UIだけで完了としない。

## 4. Phase 10.3 — 材料から、自分の芽を書く

### 到達状態

元の思いつきとつないだメモを読んで、本人が「なら、こうできそう」を書ける。芽から材料へ戻れる。

### 実装すること

- フォーカス中の種が保存先であることを示し、原文を必ず材料として含める。
- ほかの材料を選ぶ／外す、全文を見る、可能性の一文を書く。
- 材料に他の芽を選ぶ場合は、見ていた原文か芽の文かを明示し、同じ言葉を記録する。
- 芽の文章は原文と別に保存。成功後に状態をsproutへ変更。
- 同じ種の詳細・一覧カードに「できそうなこと」を表示し、由来をたどれる。
- 芽を見直す／いったん種へ戻す。原文・接続と、再編集できる芽の文を維持。
- 新しい材料が追加・編集・削除されても、確定済みの芽を自動改稿しない。
- 旧Transformは補助の「書き出し方」としてアクセスを維持。新しい芽を単なるテンプレ変換にしない。

### 完了条件

- 材料の数で芽操作がロックされない。空欄は保存不可、内容の良し悪しの採点はしない。
- 一覧で複数選んだ場合も、どの種が芽になるか保存前にわかり、変更できる。
- 既存の芽の見直しでは中心固定。新規作成中に既存芽のある中心を選んでも、入力下書きを保持し、その芽を黙って上書きしない。
- 芽保存後も、他の材料の状態や本文は変わらない。
- 接続解除と、芽作成時の材料履歴の違いを表示で説明できる。
- 芽の下書きで中断しても原文や既存の芽を破壊しない。
- 二重タップ・保存失敗の再試行で芽の重複や意図しない状態変更がない。

## 5. Phase 10.4 — 初回理解と再開

### 到達状態

初めて開いた人がすぐ書ける。興味を持った人は短い練習で、つながりと芽の違いを理解できる。

### 実装すること

- Homeの空状態に一文の約束と「メモを書く」、任意の「例で使い方を見る」。
- [中核設計の共通例](core-growth-loop.md#3-価値が生まれる一続きの例)で、選ぶ→つながりを見る→芽を書くを実操作できる。
- 練習データ・状態は実データ、検索、件数、庭便り、書出しに混ぜない。
- いつでも終了でき、後からヘルプへ戻れる。スキップ後に毎回再表示しない。
- 実操作の近くで必要な一文だけ説明。用語クイズやステップ完了の強制は入れない。
- 起動時の固定待機を見直し、ロード完了後に思いつき入力を不要に待たせない。

### 完了条件

初回・例スキップ・途中終了・再体験・2回目以降・既存ユーザーの各経路で、実データの種を失わずに利用できる。旧データのある人へ空の庭や初心者扱いの強制フローを出さない。

## 6. Phase 10.5 — 大量の整理・関連候補・再会

### 到達状態

蓄積が増えても探せて、つながりと芽をたどれる。自動候補に頼らず使え、候補があれば出会いやすくなる。

### 実装すること

- 全件の仮想化リスト、本文・題名・芽の文章の検索、任意カテゴリと状態の絞り込み。
- 「つながりなし」「つながりあり」「芽」など目的別の見方。未接続を処理待ち扱いしない。
- 焦点の接続が多い場合の件数表示・表示上限・全件リスト・検索・戻り位置。
- 正規化した共通語・カテゴリによる説明可能な候補。最大3件を初期仮説とし、候補ゼロを許容。
- 日本語の語句は空白分割だけに頼らず、文字列の正規化・部分一致など軽量な方法を評価する。単一文字一致や気分だけを関係の根拠にしない。
- 関連候補は実線と分離。「今回は見送る」で同じ組合せをしつこく出さない。手動検索は残す。
- 今日の種・庭便りから「つながりを見る」「メモを足す」「芽を見直す」へ進める。
- 既存の庭便りは保持し、意味を断定せず、実際に結んだ接続と本人が書いた芽を示す。

### 完了条件

50 / 500 / 2,000 / 5,000件の人工データと高次数の種で、全件が探索可能。検索結果や図で省いた項目を欠落と誤認させない。候補が無い・間違う・全て見送る場合も一周が成立する。

パフォーマンス値は後述の測定で判断し、「5,000件対応済み」等を件数fixtureの生成だけで主張しない。

## 7. Phase 10.6 — 統合検証と公開判定

### 自動確認

現行の `package.json` に `npm run check`（typecheck / lint / test）がある。未整備とする過去文書の記述を根拠に、検証を省略しない。

意味のある失敗・境界の試験を追加する。画面の文言をなぞるだけの試験は増やさない。

| ID | シナリオ | 必須結果 |
|---|---|---|
| D01 | v1配列、片方向・双方向・重複・自己関連、旧sprout/tree、削除済みを移行 | 原文等を維持し、無向ペア一意。合成文・接続日時を捏造しない |
| D02 | 新規メモ→接続→芽→再読込→書出し | 同じ内容・材料・接続を保持 |
| D03 | 遅い書込みが前後、連続操作、保存中再浮上 | 古いsnapshotが新しいsnapshotを上書きしない |
| D04 | 本保存失敗／本保存成功でbackup失敗 | 失敗の意味に沿った表示と再試行。二重メモを作らない |
| D05 | つなぐ／外す／同ペア再接続／連打 | pair一意、両端から見える、本文不変 |
| D06 | 元メモを編集・soft delete・復元、接続解除 | 芽を自動改稿せず、材料の状態がわかる |
| D07 | 芽保存中断・失敗・戻し・再編集 | 原文、接続、既存の芽、下書きを誤って消さない |
| D08 | A–B–Cの循環や高次数の種を表示 | 無限展開なし、非直接の線を捏造しない |
| D09 | 日本語／半角全角／長文／絵文字／題名なしを検索 | 全文を読め、検索対象・一致理由が説明どおり |
| D10 | サンプルを完走・終了・再体験 | 実データ・統計・検索・エクスポートに混ざらない |
| D11 | 全削除、アプリ再起動 | 本保存・backup・下書き・材料snapshotから内容が復活しない |
| D12 | JSON/text書出し | 接続の両端、芽の文章と由来を読める。復元UIが無い場合はそう説明する |
| D13 | 他の芽を材料として選ぶ | 原文／芽の文の見た内容とsnapshotが一致。内部材料を再帰コピーしない |
| D14 | 全削除の各段階で終了・再起動 | 保存中writerと旧版移行から内容が復活せず、削除を完了できる |
| D15 | 新規芽の中心を既存芽のあるメモへ変更 | 作成中の文を保持し、既存芽を無断置換しない |

### 表示・操作確認

- iOS実機でキーボード、バックグラウンド復帰、日本語変換、VoiceOver、文字拡大、Reduce Motionを確認。
- Webは少なくとも幅320 / 390 / 768px、キーボード操作、フォーカスの復帰、読み上げ通知を確認。
- タップ領域は製品目標44×44pt以上を基本とする。WebのCSS pxと同じ単位だと扱わない。
- 色・線・アニメーションがなくても、選択・接続・芽・保存結果が理解できる。
- 地図の操作をドラッグ・ピンチだけにしない。長い本文は本文表示で省略を解除できる。
- スクリーンショットには使用端末・画面サイズ・データ条件・コミットを付ける。古いスクリーンショットで新機能の検証を代用しない。

### 探索と速度の測定

以下は**製品の暫定目標**。未計測で、全端末に対する保証値ではない。

| 観点 | 条件 | 初期目標 |
|---|---|---|
| 入力まで | データ読込完了・Home表示後 | 主操作1回で入力欄へ。演出のための追加待機なし |
| 保存 | 短文・通常のローカル書込み、内容を考える時間は除外 | 保存タップから確定表示までp95 1秒以内を目指す |
| 検索 | 2,000件、通常長／長文が混在 | 入力が固まらず、確定文字列からp95 300ms以内を目指す |
| 図の移動 | 直接接続20件／200件の焦点 | 表示を制限しても全件到達可。焦点切替p95 300ms以内を目指す |
| 5,000件 | iOS基準端末とWebで実測 | 操作不能、落下、検索からの欠落ゼロ。時間・容量を報告 |

基準端末・OS・ビルド・本文長・接続密度・試行回数を記録する。必要な最適化は実測から決める。React描画完了を永続化完了の代わりに測らない。
材料の文章snapshotと下書きを含む保存バイト数、JSON化の時間、入力時の応答も測る。記録件数だけで容量や速度を保証せず、下書き更新で全一覧・検索・接続インデックスを再計算しない。

## 8. 初見ユーザーで確かめること

### 小さな試験の進め方

初見の人5人程度を最初の観察単位とする。統計的な保証ではなく、共通のつまずきを探すための暫定運用。事前に栄養・芽の用語を教えず、押すボタン名も伝えない。

| 課題 | 依頼文の例 | 見ること |
|---|---|---|
| 自由に残す | まだまとまっていない、最近思ったことを残してください | 分類や完成文章が必要だと誤解しない |
| 後からつなぐ | 前に残した二つを、一緒に考えたくなりました | 親を決めず、対象を探して結べる |
| 図でわかる | このメモとつながるものを見せてください | 線の意味・焦点・省略された件数を理解する |
| 芽にする | この組み合わせから、できそうなことを残してください | バッジ変更で終えず、自分の案を残せる |
| 戻って探す | 最初の思いつきと、芽の材料を見せてください | 原文が残ること、戻る場所がわかる |
| 間違いを直す | このつながりだけ外してください | メモ削除と取り違えない |
| 大量から探す | 200件の例の中から、以前の写真の思いつきを見つけてください | 検索・カテゴリ・未接続の選択肢が役立つ |
| 言葉で説明 | このアプリでは、メモがどう育つと思いましたか | 件数自動昇格や強制整理だと誤解していない |

合格の暫定目安は、主な一周を5人中4人以上が操作の助言なしで完了し、残りの人のつまずきも把握・修正すること。内容を考える時間と操作に迷う時間は分けて記録する。「90秒で芽を作る」などを利用者の課題にしない。

誤削除、保存済みの誤認、材料が消える誤解、前の場所に戻れない問題は、人数にかかわらず修正対象にする。

## 9. 価値の検証は、件数を増やすことと区別する

初期の中心指標は、**本人の記録を後からつなぎ、その関係を理解して、必要なときに自分の可能性を残せたか**。

- 自分の言葉で「これがつながった理由」を説明できるか。
- 初回練習ではなく、本人の実際のメモで一周できるか。
- 日をまたいで、過去の種に新しい気づきを足せるか。
- 種のまま残しても、未処理感・罪悪感を生まないか。
- 候補を断る、線を外す、芽を考え直すことに迷わないか。

必要な観察は同意したユーザーテストの記録から始める。分析SDKや外部へのメモ本文送信をこの設計の実装条件にしない。将来イベント計測を導入する場合も本文・検索語・材料引用を収集しない。

## 10. 公開判定と報告の形式

- [ ] Phase 10.1〜10.5の受入条件が満たされた。
- [ ] `npm run check` と必要な新規の保存・関係・芽の試験が合格。
- [ ] 旧データの非破壊移行、失敗からの回復、書出しを確認。
- [ ] オフラインで書く→後からつなぐ→図で見る→芽を書く→再起動の一周を確認。
- [ ] 大量データと高次数の種で、探索・一覧・図の挙動を実測。
- [ ] iOS実機・アクセシビリティ・初見ユーザーの結果を記録。
- [ ] 未確認や失敗を伏せず、公開判断に影響する項目を整理。

実機や人による確認がその環境で実施できない場合、コード上の確認だけで合格にしない。準備できるテストデータ・手順・記録表を揃え、実装済みと検証待ちを分けて引き継ぐ。

実装担当の最終報告には、完了Phase、コミット、変更ファイル、試験結果、実機・初見検証の有無、残課題を含める。一般的な「改善しました」だけで中核体験の完成を宣言しない。
